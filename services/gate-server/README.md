# facegate-server

얼굴인식 게이트 서버. AI 서버의 감지 결과로 출입을 판정하고 게이트를 연다.

## 실행

Node.js 24 이상. 이 폴더에서 순서대로 실행한다.

    npm install
    cp .env.example .env

실행 전에 `.env`의 `INITIAL_ADMIN_ID`, `INITIAL_ADMIN_PASSWORD`에 설치자가 정한 값을 넣는다. 값은 `.env`에만 보관하고 문서, 예시 파일, 로그, 저장소에 복사하지 않는다. 아이디는 영문 소문자, 숫자, `. _ -`로 3~32자이며 비밀번호는 빈 문자열만 거절한다. `dev`는 예약 개발 계정이므로 초기 아이디로 쓰지 않는다. 게이트와 단말은 관리자 웹 **게이트** 화면에서 추가하고 연결한다(D-57). 예전 `config/gates.json`이 있으면 DB에 게이트가 없을 때 처음 한 번만 가져온다.

관리자 웹을 함께 띄우려면 저장소의 `apps/admin-web`에서 먼저 `npm install`, `npm run build`를 실행한다. 이 폴더로 돌아와 `npm start`를 실행하면 된다. `ADMIN_WEB_DIR` 기본값은 `../../apps/admin-web/dist`이며 빌드가 없으면 서버 API만 제공한다.

첫 관리자는 서버 시작 때 관리자가 0명인 경우에만 만든다(이름은 아이디). 값이 하나라도 비면 생성하지 않고 경고하므로 `.env`를 채운 뒤 다시 시작한다. 기존 관리자가 있으면 이 변수로 계정이나 비밀번호를 덮어쓰지 않는다. 로그인 뒤 "계정 정보 확인"에서 현재 비밀번호로 확인하고 아이디 또는 비밀번호를 바꾸거나 "그대로 쓰기"를 선택한다. 내 비밀번호 변경은 이후 설정 화면에서 한다.

`APP_ENV`는 `development` 또는 `production`이고 빈 값은 production이다. 개발 PC에서만 development로 지정한다. 개발 시작마다 `dev` 계정을 만들거나 비밀번호를 `1234`로 되돌리며 경고 한 줄과 웹 맨 위 "개발 모드" 줄을 표시한다. 운영 시작 시 이 계정이 남아 있으면 웹과 단말 세션까지 삭제하고 경고한다. 운영 PC에서 개발 모드를 사용하지 않는다.

확인: `npm test`, `npm run typecheck`, `npm run lint`.

## 관리자 웹 단말 영상 확인 (D-49)

게이트 2대, 단말 2대 기준으로 현황 화면에 두 단말 영상을 2열로 고정해 동시에 표시한다. 각 영상 가까이에 해당 게이트의 1회 개방 폼을 두며 사유·방문객 입력과 대기·성공·실패 결과는 각자 유지한다. 모달이나 게이트 선택·전환 없이 각 영상을 독립 연결하고 현황 화면을 떠나면 두 영상 연결을 모두 종료한다. 성공 문구는 "개방 신호를 보냈습니다"이며 실제 개폐 센서 없는 열림/닫힘 표시는 하지 않는다. 미지원 닫기·재시작·NFC 버튼은 추가하지 않는다. 서버에 [FFmpeg](https://ffmpeg.org/download.html) 5 이상을 설치하고 `ffmpeg -version`으로 확인한다. RTSP `-timeout` 옵션의 뜻이 5.0에서 바뀌어 4.x 이하에서는 접속 대기 시간이 맞지 않는다. PATH에 없다면 `.env`의 `FFMPEG_PATH`에 실행 파일 경로만 지정한다. 단말 = 카메라가 달린 안드로이드 기기 하나다(D-56). 단말의 RTSP 계정은 단말을 연결할 때 서버가 만들어 DB에 두며 브라우저에 전달하지 않는다. 다만 FFmpeg 실행 인자에 RTSP 주소가 그대로 들어가므로 서버 PC의 작업 관리자 등에서 인증값이 보인다. 서버 PC는 전용 장비(D-09)라 이를 허용한다. FFmpeg가 없거나 단말 영상이 응답하지 않아도 서버의 나머지 기능은 시작하고, 영상 연결만 실패한다.

서버가 RTSP/TCP를 JPEG 장면(5fps, 가로 960px)으로 변환해 가장 최근 장면 하나만 메모리에 둔다. 웹은 `GET /api/admin/terminals/:terminalKey/frame`으로 0.5초마다 장면 한 장을 받는다. 오래 열린 응답이 없어 브라우저의 주소당 연결 수(6개)를 차지하지 않는다. 사내망 방문객 확인용이며 음성, 영상 저장, 전체 앱 화면 미러링은 하지 않는다. 단말의 AI 분석용 원본 RTSP 설정은 바꾸지 않는다. 같은 단말 영상을 보는 관리자는 변환 프로세스 하나를 공유하고, 10초 동안 장면 요청이 없으면 종료한다. 동시 변환은 최대 8대이며 초과하면 503 `too many terminal videos open`을 돌려준다.

장면은 WEB 세션 인증을 매 요청 거치고 private/no-store로 제공한다. 첫 장면은 10초, 그 뒤 장면 갱신은 5초까지 기다리며 넘으면 변환을 끄고 5초 뒤 다시 시도한다. 웹은 2초보다 오래된 장면(`X-Frame-Age-Ms`)이나 받지 못한 장면을 감추고 "영상 끊김"을 표시하며, 장면이 다시 오면 저절로 이어서 보여준다. FFmpeg가 예상치 않게 끝나면 주소 없이 `terminal <terminalKey> video exited code <c>` 한 줄을 남긴다. 영상은 방문객 확인을 돕고 기존 수동 개방 권한과 사유 입력, 작업 이력 규칙은 유지한다. 호출 버튼의 자동 알림과 통화 기능은 미구현이며 별도 단계다. 실제 단말 영상과 실물 릴레이 동작은 미검증이다.

## 키 운영 (D-36)

| 키               | 쓰는 곳                           | 인증                                   |
| ---------------- | --------------------------------- | -------------------------------------- |
| AI 연동 키       | `/api/modules/camera/ai`, `/file` | `X-Ingest-Key`                         |
| 관리자 계정      | `/api/admin`                      | 로그인 쿠키 `facegate_session` (8시간) |
| 단말 관리자 토큰 | `/api/terminal/admin`             | `X-Terminal-Admin-Token` (10분)        |
| 단말 토큰        | 단말 WebSocket                    | `Authorization: Bearer`                |

- AI 연동 키는 로그인한 관리자가 설정에서 발급한다(`POST /api/admin/settings/ingest-key`). 전체 키는 발급 응답에서 한 번만 보여 주고 서버에는 해시와 마지막 4자리만 남긴다. 받은 키는 AI 서버 설정에만 넣는다.
- 발급 상태는 `GET /api/admin/settings/ingest-key`로 확인한다. 재발급하면 이전 키는 즉시 무효이며 서버 재시작은 필요 없다. 발급 전 AI 요청은 모두 401이다. 선택 변수 `INGEST_KEY`는 DB에 발급 키가 없을 때만 최초 시드로 쓰인다.
- 로그인 5회 실패 시 10분 잠금. 잠긴 계정은 423이므로 아이디 존재 여부가 드러날 수 있다(사내망 전용으로 허용). 관리자 작업은 `GET /api/admin/audit-logs`로 확인한다. credentials 이력에는 실제 아이디와 비밀번호 대신 변경 여부만 남긴다.
- `.env`와 `gates.json`은 저장소와 메신저에 올리지 않는다. 관리자 웹은 `TLS_CERT_FILE`, `TLS_KEY_FILE`을 주면 HTTPS(`HTTPS_PORT`, 기본 8443)로만 열린다. 서버 PC 설치, 인증서, 시간 맞춤, 백업과 복구는 `docs/11_설치운영.md`.
