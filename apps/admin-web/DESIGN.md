# FaceGate 관리자 웹 디자인 기준

사내 출입 관리 도구. 사용자가 제공한 초안의 짙은 사이드바, 밝은 작업 영역, 파란 주요 버튼을 기준으로 한다. 기존 베이지 바탕과 가로 메뉴는 대체한다.

## 금지 (D-44)

- 숫자 카드, 차트, 장식 아이콘, 그라데이션, 그림자, 이모지, 둥근 카드 묶음
- 화면의 가운뎃점(·) 구분자. 구분은 표의 칸, 쉼표, 줄바꿈으로
- "대시보드"라는 말. 첫 화면은 "현황"

| --------- | ------- | ----------------------------- |

## 글꼴과 크기

- Pretendard Variable, 없으면 시스템 고딕
- 본문 14px, 표 13px, 화면 제목 24px(700), 구역 제목 17px(650)

## 형태

- 왼쪽 사이드바 216px: "FaceGate", 메뉴(현황, 직원, 출입 기록, 설정, 작업 이력). 짙은 바탕, 선택된 메뉴는 밝고 굵은 글씨로 표시하고 나머지는 낮은 명도의 글씨로 구분한다. 선택 배경과 왼쪽 색띠는 두지 않고 호버 시 글자색만 밝게 한다. 작은 창에서는 폭을 줄인다
- 공통 Header: 상단 헤더 기본 높이 64px. 오른쪽에 관리자 이름과 로그아웃만 표시한다. 제품명은 사이드바 왼쪽 위 한 곳에만 둔다. 가짜 지점 선택이나 알림 기능을 추가하지 않는다
- 공통 Footer: 제품 이름과 저작권 문구를 회색 바탕에 표시한다. Layout에서 본문 뒤에 한 번 배치하고 긴 주소는 줄바꿈한다. 본문이 짧으면 화면 하단에 위치하고 길면 본문 아래로 이어진다
- 웹에는 개발 모드 표시를 두지 않는다. 개발 모드는 서버 시작 경고로만 알린다
- 본문 최대 폭 1640px, 좌우 여백 28px. 밝은 회색 바탕 위 흰 작업 영역으로 묶되 상자 안에 상자를 중첩하지 않는다
- 표: 가로 구분선, 행 높이 42px, 줄무늬 없음, 머리 행은 옅은 청회색 바탕
- 버튼 높이 36px, 모서리 4px. 주 버튼은 --accent 채움, 나머지는 테두리만. 위험한 동작은 --danger 테두리
- 출입 결과: 정상은 --muted 글씨, 문제는 결과 글씨를 --danger로 표시하고 해당 행 전체에 --warn-bg를 적용한다. 결과 칸만 별도 바탕을 넣지 않는다
- 직원 얼굴 사진: 0장은 회색 "미등록", 등록된 사진은 "6장"처럼 수량으로 표시한다. 퇴사자의 0장은 "없음"으로 표시하고 얼굴 사진 수 때문에 셀이나 행에 경고 배경을 넣지 않는다

## 현황 배치 (A-02, A-14, D-49)

- 등록된 게이트 수에 맞춰 모든 게이트를 표시한다. 게이트 수를 두 대로 고정하지 않는다. 작업 영역은 기본 최소 폭 480px를 기준으로 화면 폭에 맞게 열 수를 정하고, 남은 영역이 좁으면 한 열로 배치한다. 마지막 행에 게이트가 적어도 다른 행과 같은 폭을 유지한다.
- 한 페이지에는 최대 4대의 영상과 개방 폼을 표시하고, 5대 이상이면 이전과 다음 페이지로 모든 게이트를 탐색한다. 현재 페이지의 영상만 연결하며 페이지를 떠나면 중계를 해제한다. 이 기준은 등록 수 제한이 아니라 화면 단위다. 서버가 8카메라까지 동시에 캡처하므로 두 관리자가 서로 다른 페이지를 봐도 영상이 나온다. 모달은 두지 않는다.
- 각 영역은 게이트 이름과 연결 상태 아래에 해당 단말 영상과 사유·방문객 입력, 메모, 1회 개방 버튼을 나란히 둔다. 좁은 창에서는 영상 아래에 입력을 둔다. 원본 영상은 자르지 않고 전체를 표시한다.
- 각 폼의 입력과 요청 대기·성공·실패 결과, 영상 요청은 독립적이다. 페이지를 바꾸거나 다른 게이트를 조작해도 입력과 결과를 초기화하지 않는다. 게이트는 배열 순서가 아닌 고유 ID로 구분한다.
- 구분은 제목, 간격, 정렬과 필요한 구분선만 사용한다. 최근 출입 표와 오늘 원격 개방 이력은 두 영상 영역 아래에 나란히 두고 좁은 창에서는 세로로 쌓는다.
- 연결 상태와 실제 개폐 상태를 구분한다. 성공은 "개방 신호를 보냈습니다"로 알리고 실제 개폐 센서 없는 열림/닫힘은 표시하지 않는다. 미지원 닫기·재시작·NFC 버튼은 추가하지 않는다. 호출 알림과 음성은 미구현이며 별도 범위다.

## 영역 크기와 정렬

- 빈 데이터, 불러오는 중, 오류 때문에 작업 영역이 급격히 작아지지 않게 기본 크기를 유지한다.
- 게이트 영역은 같은 행 높이로 맞춘다. 각 작업 영역은 최소 416px, 개방 입력은 최소 330px를 확보하고 버튼을 하단에 맞춘다. 결과 안내도 최소 40px 자리를 확보한다. 개수에 의존하는 세로 구분선이나 왼쪽 상태띠는 두지 않는다.
- 영상은 0.5초마다 최근 장면을 받아 바꾼다. 받지 못했거나 2초보다 오래된 장면은 감추고 "영상 끊김"을 표시하며, 확인 중이나 끊김에도 260px 높이를 유지한다. 원본 비율은 보존한다.
- 최근 출입과 오늘 원격 개방 영역은 각각 높이 360px로 통일한다. 데이터가 많으면 표 영역 안에서 스크롤하고 머리 행은 유지한다. 데이터가 없을 때도 동일 높이다.
- 좁은 창에서 세로 배치로 바뀌어도 같은 종류의 영역은 같은 기본 크기를 유지한다. 문구가 길어지면 잘라 숨기지 않고 필요한 만큼만 늘린다.

## 얼굴 등록과 예외 개방

- 신규 직원 사진은 정면 1, 정면 2, 좌측, 우측, 상향, 하향의 고정된 6칸을 제공한다. 각 칸은 같은 기본 크기를 유지하고 동의 전에는 파일 선택을 비활성화한다. 여섯 칸을 모두 채워야 등록할 수 있다.
- 직원은 얼굴 인식 실패 시 NFC 사원증을 우선 사용한다. 관리자 웹의 원격 개방은 방문객을 기본 사유로 두고, 얼굴과 NFC를 사용할 수 없는 직원은 "직원 인증 불가"를 선택한다. 실제 NFC 기능은 별도 개발 단계다.

## 설정과 작업 이력

- 설정은 흰 작업 영역 하나에서 출입 설정, AI 연동 키, 관리자 계정, 내 비밀번호를 제목과 간격으로 구분한다. 위쪽 두 영역은 같은 높이를 유지하고 각 영역은 최소 200px를 확보한다. 입력이 많은 아래 영역은 필요한 만큼 늘린다.
- 설정 입력의 기본 테두리와 영역 사이 가로 구분선만 사용한다. 키와 안내 문구에 별도 배경이나 장식 배지를 붙이지 않는다. 비밀번호는 공통 눈 아이콘을 사용하고 제출하면 다시 가린다.
- 작업 이력은 최근 200건 안내와 표로 구성한다. 표 영역은 최소 336px를 유지하며 긴 내용은 표 안에서 가로 스크롤한다.

## 장식과 상호작용

반복해서 사용하는 업무 화면을 기준으로, 입력과 판단과 조작에 필요한 요소만 둔다.

- 메뉴와 버튼에는 호버 밑줄, 밑줄이 자라는 효과, 반짝임을 추가하지 않는다. 버튼처럼 쓰는 링크에도 같은 기준을 적용한다. 본문 안의 링크는 클릭할 수 있다는 점이 분명해야 한다. [GOV.UK 링크 지침](https://design-system.service.gov.uk/styles/links/)
- 호버 시 버튼이나 행이 커지거나 떠오르지 않게 한다. 레이아웃 이동, 그림자, 반복 애니메이션 대신 필요한 경우 옅은 배경이나 글자색 변화만 쓴다. 자동 갱신할 때 표가 순서대로 나타나거나 숫자가 움직이는 연출을 넣지 않는다.
- 구역마다 상자와 외곽선을 두르거나 상자 안에 상자를 중첩하지 않는다. 제목, 간격, 정렬로 먼저 구분하고 표의 행, 입력 칸, 대화상자 경계처럼 식별에 필요한 선을 남긴다.
- 제목, 안내 문구, 사진 등록 칸, 빈 공간에 구분용 배경색을 반복해서 넣지 않는다. 안쪽 영역은 상위 작업 영역의 바탕을 그대로 사용하고 간격과 정렬로 구분한다.
- 카드나 작업 영역 왼쪽에 색 상태띠를 두르지 않는다. 왼쪽 테두리, 가상 요소, 그림자로 같은 장식을 만들지 않으며 상태는 글자와 필요한 표 칸으로 표시한다.
- 기존 색과 글자 크기를 재사용한다. 정상 상태마다 배경색과 배지를 붙이지 않으며, 문제가 있는 출입 기록 행과 주요 동작만 강조한다. 상태는 색을 보지 않아도 글자로 알 수 있게 한다.
- 제목 옆 장식 아이콘, 모든 상태를 감싸는 알약 모양 배지, 불필요한 화살표와 느낌표를 넣지 않는다. 비밀번호 보기처럼 조작에 필요한 아이콘에는 이름과 동작을 제공한다.
- 큰 소개 문구, 영문 소제목, 과한 자간, 구역마다 다른 제목 크기를 추가하지 않는다. 내용이 적어도 빈 공간을 채우려고 요약 카드나 장식 요소를 만들지 않는다.
- 키보드로 선택한 위치와 선택된 메뉴는 계속 식별할 수 있어야 한다. 불필요한 외곽선을 줄이기 위해 포커스 표시를 일괄 제거하지 않는다. [W3C 포커스 표시 지침](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

## 문구와 주석

- 제목과 버튼만으로 알 수 있는 내용을 설명 문단으로 반복하지 않는다. 각 입력 칸에 안내를 기본으로 붙이지 말고, 단위나 형식처럼 입력에 필요한 정보만 가까이에 짧게 둔다. [DWP 입력 안내 지침](https://design-system.dwp.gov.uk/guidance/hint-text)
- 검색 결과 없음, 불러오는 중, 불러오기 실패를 구분한다. 빈 화면에는 상태 한 줄과 필요한 동작만 두고 기능 소개나 시작 가이드를 반복하지 않는다.
- 저장과 개방 결과는 짧게 알린다. 과장된 칭찬, 홍보 문구, 장식적인 성공 배너를 넣지 않는다. 오류는 문제와 다음 조치를 설명한다.
- 생체정보 동의, 퇴사와 사진 삭제의 영향, 한 번만 볼 수 있는 연동 키, 필수 입력 조건은 유지한다. 보안 경고도 유지한다.
- 화면에는 사용자에게 필요한 상태와 동작을 쓴다. API 경로, 구현 메모, 작업 진행 주석은 화면 설명으로 노출하지 않는다.
- 코드 주석은 코드만 읽어서는 알기 어려운 이유와 제약을 설명할 때 남긴다. 동작을 그대로 읽어 주는 주석이나 작업 일지는 추가하지 않는다.

문구를 다듬을 때의 예시이며, 기능과 입력 규칙은 그대로 유지한다.

| -------------------------- | ------------------------------ |
| 계정 정보 확인 안내        | 현재 비밀번호로 확인해 주세요. |
| 직원과 기록의 빈 검색 결과 | 검색 결과가 없습니다.          |
| 작업 이력 조회 범위        | 최근 200건                     |

## 화면 검토 기준

- 이 요소가 사용자의 입력, 판단, 조작에 필요한지 확인한다. 없어도 같은 일을 할 수 있으면 추가하지 않는다.
- 기본 상태, 호버, 키보드 선택 상태를 함께 확인한다. 클릭할 수 없는 요소에 손 모양 커서나 호버 효과를 붙이지 않는다.
- 안내를 줄인 뒤에도 작업 결과, 위험, 복구 방법을 알 수 있는지 확인한다.
- 각 기능의 구현과 검증 결과를 먼저 보여 주고, 사용자 승인 후에만 커밋, 푸시, 머지한다.
