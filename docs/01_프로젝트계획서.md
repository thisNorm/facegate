# 01. 프로젝트 계획서

| 항목 | 내용 |
|---|---|
| 프로젝트명 | FaceGate (사옥 얼굴인식 출입 시스템) |
| 작성일 | 2026-10-27 |
| 버전 | 0.1 (초안) |

## 1. 배경과 목적

사옥 입구에 스피드게이트를 설치합니다. 게이트 업체는 **시공과 배선만** 맡기 때문에, 얼굴인식부터 게이트 열림 신호까지는 우리가 직접 만들어야 합니다.

목표는 다음과 같습니다.
- 등록된 직원은 카드 없이 얼굴만으로 멈추지 않고 통과
- 얼굴 인식이 안 될 때는 사원증(NFC 스티커 부착)을 대서 통과
- 미등록자·권한 없는 사람은 통과 차단, 기록 남김
- 관리자가 웹에서 직원 얼굴 등록, 권한 관리, 출입 기록 조회

## 2. 범위

### 포함
| 하위 프로젝트 | 설명 |
|---|---|
| A. 게이트 서버 | AI 서버에서 인식 결과를 받아 출입 허가를 판단하고, 게이트 열림 신호를 보내고, 출입 기록을 저장 |
| B. 게이트 단말 앱 (Android) | 게이트 옆 화면. 인식 안내와 결과 표시, 카메라 영상 송출, **NFC 사원증 읽기·발급**, 얼굴 등록 모드 |
| C. 웹 관리자 | 직원·얼굴 등록, 출입 권한, 출입 기록, 게이트·장비 상태, 원격 개방 |

### 제외 (이번 범위 아님)
- 얼굴인식 AI 모델 새로 개발: 기존 시스템와 같은 AI 프로그램을 쓰되, 게이트용 동작(Q-12 재전송 등)은 요청자가 직접 수정 (D-19)
- 게이트 선정·구매·시공·배선: 시설 쪽 / 게이트 업체 담당 (D-27). 우리는 게이트가 정해진 뒤 제어 프로토콜만 맞춤
- 방문객 사전 예약·임시 출입증: 만들지 않음. 방문객은 인사과가 원격 개방 (D-13)
- 근태·급여 연동: 필요 시 2차 (Q-07)

## 3. 진행 순서 (D-26: 입주 2026년 12월~2027년 1월)

남은 기간이 약 6~9주라서 **입주 때 꼭 필요한 기능(1차)만 먼저 열고**, 나머지는 입주 후 단계적으로 붙입니다.

| 단계 | 기간 (목표) | 내용 | 끝났다는 기준 |
|---|---|---|---|
| **0. 준비** | 10/27 ~ 11/2 | 단말(WA8059T) 1대·네트워크 릴레이 모듈 구매. 게이트는 시설 쪽에서 별도 선정 (D-27) → 선정되면 08 질의서 전달 | PoC 장비 도착 |
| **1. PoC** | 10/28 ~ 11/9 (2주) | 단말 1대 RTSP 송출 → 사옥용 AI(게이트 설정 AI-01~04) → 게이트 서버 최소판(appear 수신 → 릴레이 → LED, 단말 결과 화면). 72시간 송출, 응답 시간, 위조 시험 | 03 문서 8장 기준 통과 → 안 B 확정 |
| **2. 1차 개발** | 11/10 ~ 11/30 (3주) | 1차 범위(아래 표) 전부 | 책상 위에서 전 기능 시연 |
| **3. 현장 설치·시범** | 12/1 ~ 12/14 | 실제 게이트 배선 연결, 전 직원 얼굴 등록(인사과 일괄 촬영), 일부 직원 시범 운영 | 출근 시간 실측: 본인 거부율·응답 시간 |
| **4. 입주 오픈** | 12월 중순 ~ 1월 | 1차 정식 운영 | — |
| **5. 1.5차** | 입주 후 ~4주 | NFC 사원증 (스티커 발급·출입) | 전 직원 스티커 발급 |
| **6. 2차** | 그 이후 | 나머지 기능 | — |

### 단계별 범위

| 단계 | 포함 요구사항 | 비고 |
|---|---|---|
| **1차 (입주)** | 게이트 서버 FR-S 전부(퇴장 FR-S-13은 Q-05 결정에 따름), 단말 FR-T-01~13·18(얼굴 등록 모드), 웹 관리자 FR-A-01·02·03(기존 파일 업로드 `WEB_UPLOAD`·단말 관리자 모드 촬영 `TERMINAL`, D-48)·03-1·03-2·04·06·08·09·09-1·11, AI 변경 AI-01~04·06 | 얼굴이 안 될 때 대체 수단 = **인사과 원격 개방(FR-A-09)**. 방문객도 원격 개방 |
| **1.5차** | NFC FR-N 전부 (얼굴+NFC 설정 포함) | 발급 APDU 중계가 가장 복잡 → PoC 기간에 스티커 몇 장으로 미리 시험 |
| **2차** | 방문객 호출·손님 동반 FR-V 전부, 셀프 업로드 FR-A-12, 엑셀·ZIP 일괄 등록 FR-A-03-3, 실시간 현황 FR-A-07, 미등록자 목록 FR-A-10, 권한 그룹 FR-A-05, AI-05(위조 방지, PoC 결과에 따라 앞당김), AI-07·08 | |

**일정의 가장 큰 위험**
1. **게이트 선정·프로토콜 확정 시점** (우리가 정하지 않음, D-27): 게이트가 늦게 정해져도 개발은 공통 명령 + 드라이 접점 어댑터로 진행. 선정 즉시 08 질의서를 보내 어댑터를 맞추고, 12월 초 배선 연결 전까지 프로토콜을 받아야 함
2. **모델 라이선스(Q-34)**: 상업 사용이 안 된다고 확인되면 모델 교체·재측정이 필요 → 0~1단계 중 확인
3. **전 직원 얼굴 등록**: 50~200명 촬영·동의서 → 3단계 첫 주에 인사과 일괄 진행 (동의서 양식 Q-32는 11월 중 확정)

## 4. 기존 자산 재사용

| 자산 | 재사용 방법 |
|---|---|
| 얼굴인식 AI 서버 (`/api/modules/camera/ai`) | 게이트 서버가 엣지서버와 **같은 API 경로·형식**을 제공 → AI 프로그램은 서버 주소와 키만 바꾸면 됨 |
| 기존 엣지 서버 기술 스택 (Node.js, React+Vite, Docker, go2rtc) | 게이트 서버·웹 관리자에 같은 스택 사용 |
| 원격 관리 서버 | 게이트 서버가 Heartbeat를 보내 상태 감시·원격 업데이트 |
