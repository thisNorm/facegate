# 11. 설치와 운영

버전 0.3 · 2026-11-04 · 1차 P6 (폴더 권한, HTTPS, Docker, 시간 맞춤, 백업). 사진 암호화는 다음 차례

게이트 서버와 관리자 웹은 서버 PC 한 대에 Docker로 올린다. 단말 앱과 AI 서버는 각자 설치한다.

## 1. 서버 PC 준비 (리눅스)

1. Docker와 Docker Compose를 설치한다.
2. 아래 "고정 IP"대로 서버 PC의 IP를 고정한다.
3. 2장대로 전용 계정, 폴더와 권한을 만든다. 백업은 가능하면 데이터와 다른 디스크에 둔다.
4. 저장소를 받고 `services/gate-server/.env.example`을 `.env`로 복사해 첫 관리자 아이디와 비밀번호를 넣는다. 경로 값은 `compose.yaml`이 정하므로 비워 둔다.
5. 3장대로 인증서를 만든다.
6. 저장소 맨 위에서 실행한다.

       docker compose up -d --build
       docker compose logs -f gate-server

   `[FaceGate] listening on 8080`, `https on 8443`, `[backup] ...` 줄이 나오면 된다.

호스트 네트워크로 띄운다. 단말을 연결할 때 QR에 서버 PC의 사내망 IP를 넣어야 하고, 단말 영상(RTSP)도 서버 PC에서 바로 받아야 하기 때문이다. 방화벽은 8080(단말, AI)과 8443(관리자 웹)을 사내망에만 연다.

**고정 IP:** 서버 PC의 IP는 바뀌면 안 된다. 단말(연결 QR), AI 서버(게이트 서버 주소), HTTPS 인증서, 인사과 PC의 관리자 웹 주소가 모두 이 IP를 쓰기 때문이다. IP가 바뀌면 단말을 다시 연결하고 AI 설정을 고치고 인증서를 다시 만들어야 한다.

1. 서버 PC에서 지금 IP와 랜 카드 주소(MAC)를 확인한다. 리눅스는 `ip addr`, Windows는 `ipconfig /all`.
2. 사내 공유기 관리 화면(보통 `192.168.0.1` 또는 `192.168.1.1`)에 들어가 "DHCP 고정 할당"(제품에 따라 "고정 IP 할당", "주소 예약")에서 그 MAC에 지금 IP를 묶는다.
3. 서버 PC를 다시 켜고 같은 IP를 받는지 확인한다.

공유기 설정을 바꿀 수 없으면 서버 PC 쪽에서 IP를 직접 고정한다(우분투: 설정 → 네트워크 → IPv4 → 수동, Windows: 네트워크 어댑터 → IPv4 속성). 이때는 다른 기기가 자동으로 받는 범위 밖의 주소를 고른다. 공유기에서 8080, 8443을 인터넷으로 여는 포트 포워딩은 하지 않는다.

Docker 없이 쓰려면 `services/gate-server/README.md`의 실행 순서를 따르고 `.env`에 아래 값들을 직접 넣는다.

## 2. 저장 암호화와 폴더 권한

직원 얼굴 사진은 생체정보다. 동의서 6항에서 "암호화 등 필요한 보호 조치"를 약속했다. 서버 PC는 다른 업무와 함께 쓰는 공용 PC일 수 있으므로 디스크를 통째로 암호화하는 방법을 기본으로 삼지 않는다.

**지금:** 사진 파일은 암호화하지 않고 아래 폴더 권한으로만 막는다. 같은 PC의 다른 일반 계정은 읽을 수 없지만, PC 관리자 계정이나 디스크를 떼어 간 사람은 읽을 수 있다.

**다음에 할 일 (서버가 사진을 직접 암호화):** 디스크를 포맷하거나 PC 설정을 바꾸지 않는 방법이다.

- 게이트 서버가 얼굴 사진을 저장할 때 AES-256-GCM으로 잠그고, 관리자 웹과 AI에 보낼 때만 메모리에서 풀어 보낸다. 풀린 사진은 디스크에 남지 않는다.
- 열쇠는 32바이트 무작위 값이 든 파일 하나다. 서버가 처음 켤 때 없으면 만든다. 개발 PC도 같은 코드로 돌고, 암호화를 끄는 설정은 두지 않는다.
- 열쇠는 프로젝트 폴더, 데이터 폴더, 백업 폴더 밖에 둔다. 리눅스는 `/srv/facegate/keys/face.key`, Windows는 `C:\ProgramData\FaceGate\keys\face.key`이다. 서버 계정만 읽게 막고, 컨테이너에는 읽기 전용으로 붙인다. 개발 PC는 git이 무시하는 위치에 둔다.
- 같은 열쇠의 사본 하나를 서버 PC 밖(인사과 금고 등)에 USB나 종이로 둔다. 서버 PC가 고장 나면 새 PC에 백업과 이 사본을 함께 넣어 되살린다. 열쇠를 새로 만들면 기존 사진은 풀 수 없다.
- 사진 폴더나 백업만 가져가서는 열 수 없고, 열쇠까지 함께 가져가야 열린다.

**이 시스템 전용 디스크일 때만 (디스크 전체 암호화):** 서버 PC나 디스크가 출입 시스템 전용일 때는 디스크 전체를 암호화해도 된다. **공용 디스크에서는 하지 않는다. 아래 `luksFormat`은 그 디스크의 기존 내용을 모두 지운다.**

- 우분투를 새로 깔 때 설치 화면에서 "디스크 암호화(LVM과 암호화)"를 고르면 시스템 디스크 전체가 LUKS로 암호화된다.
- 전용 데이터 디스크를 붙일 때(`/dev/sdb`는 예시, `lsblk`로 꼭 확인):

      sudo cryptsetup luksFormat /dev/sdb
      sudo cryptsetup open /dev/sdb facegate_data
      sudo mkfs.ext4 /dev/mapper/facegate_data
      sudo mkdir -p /srv/facegate
      sudo mount /dev/mapper/facegate_data /srv/facegate

  정전 뒤 사람 없이 열리게 이 PC의 TPM에 열쇠를 묶는다(`sudo systemd-cryptenroll --tpm2-device=auto /dev/sdb`, `/etc/crypttab`에 `facegate_data /dev/sdb none tpm2-device=auto`).
- Windows 전용 드라이브는 BitLocker를 켠다(`manage-bde -on D: -RecoveryPassword`).
- LUKS 암호와 BitLocker 복구 키는 서버 PC 밖에 둔다.

디스크 암호화는 PC나 디스크를 잃어버렸을 때만 막는다. PC가 켜져 있으면 디스크는 열려 있으므로, 같은 PC를 쓰는 다른 사람은 폴더 권한으로 막는다.

**폴더 권한:** 컨테이너는 root가 아닌 출입 서버 전용 계정 `facegate`로 돈다(`compose.yaml`의 `user`). 1000번처럼 정해진 번호를 쓰지 않는 까닭은, 우분투에서 1000번은 보통 PC에 처음 만든 사람 계정이라 공용 PC에서는 그 사람이 사진을 읽게 되기 때문이다. 아무도 로그인할 수 없는 계정을 따로 만들고 데이터와 백업은 그 계정만 읽고 쓰게 한다.

    sudo useradd --system --no-create-home --shell /usr/sbin/nologin facegate
    sudo mkdir -p /srv/facegate/data /srv/facegate/backup /srv/facegate/certs
    sudo chown -R facegate:facegate /srv/facegate/data /srv/facegate/backup
    sudo chmod 700 /srv/facegate/data /srv/facegate/backup
    sudo chown root:facegate /srv/facegate/certs && sudo chmod 750 /srv/facegate/certs
    # 저장소 맨 위에 .env를 만들어 계정 번호를 적는다 (git에는 올라가지 않는다)
    echo "FACEGATE_UID=$(id -u facegate)" >  .env
    echo "FACEGATE_GID=$(id -g facegate)" >> .env

`docker` 그룹에 든 계정은 컨테이너로 root 권한을 얻을 수 있으므로, 서버 PC 관리 담당자 외에는 `docker` 그룹에 넣지 않는다.

**확인:** `ls -ld /srv/facegate/data`가 `drwx------`이면 된다. 다른 계정으로 `ls /srv/facegate/data/files/faces`를 하면 거절되어야 한다.

얼굴 사진 폴더 이름은 직원 번호(`faces/7/임의이름.jpg`)다. 파일이나 폴더 이름에 직원 이름을 쓰지 않아 파일 목록만으로는 누구 얼굴인지 알 수 없다.

## 3. HTTPS 인증서

관리자 웹만 HTTPS(8443)로 연다. 단말과 AI는 사내망 HTTP(8080)를 그대로 쓴다. 단말 토큰과 AI 연동 키는 그 기기에만 있고, 관리자 비밀번호와 세션은 HTTPS로만 오간다. HTTP로 관리자 웹에 들어오면 HTTPS 주소로 넘기고, HTTP 관리자 API는 403으로 막는다.

사내망 전용이라 회사가 직접 만든 인증서를 쓴다. `192.168.0.10` 자리에 서버 PC IP를 넣는다.

    cd /srv/facegate/certs
    openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
      -subj "/CN=FaceGate" -addext "subjectAltName=IP:192.168.0.10" \
      -keyout server.key -out server.crt
    sudo chown root:facegate server.key && sudo chmod 640 server.key

`server.crt`를 인사과 PC마다 "신뢰할 수 있는 루트 인증 기관"에 넣는다(Windows: 파일 더블클릭 → 인증서 설치 → 로컬 컴퓨터). 넣지 않으면 브라우저가 경고를 띄운다. 관리자 웹 주소는 `https://서버IP:8443`이다. 서버 IP가 바뀌면 인증서를 다시 만든다.

### 핸드폰으로 열기 주소 (D-62)

`.env`의 `PHONE_BASE_URL`에 직원 핸드폰이 여는 서버 주소를 넣는다(예: `https://gate.회사도메인:8443`). 비우면 이 기능이 꺼진다.

- 핸드폰은 사내 와이파이에 붙어 있어야 서버에 닿는다.
- 위의 회사 자체 인증서로는 핸드폰마다 경고가 뜬다. 회사 도메인이 있으면(홈페이지나 메일 주소) 도메인 관리 화면에 `gate.회사도메인 → 서버 PC 사내 IP` 기록을 더하고, Let's Encrypt의 DNS 확인 방식으로 정식 인증서를 받는다. 서버를 인터넷에 열 필요는 없다. 인증서는 90일마다 바뀌므로 `certbot`이나 `acme.sh`로 자동 갱신하고, 받은 파일을 `TLS_CERT_FILE`, `TLS_KEY_FILE`에 넣는다.
- 공유기가 바깥 DNS의 사내 IP 답을 막으면(DNS 리바인딩 보호) 그 도메인만 예외로 넣는다.

## 4. 시간 맞춤

출입 기록 시각, 로그인 세션 만료, 03시 사진 정리와 04시 백업이 모두 기기 시계를 쓴다. 기기마다 자동 시간 맞춤을 켠다.

| 기기 | 방법 | 확인 |
|---|---|---|
| 서버 PC (리눅스) | `sudo timedatectl set-ntp true` | `timedatectl status`에서 `System clock synchronized: yes` |
| 서버 PC (Windows로 운영할 때) | 설정 → 시간 및 언어 → 자동으로 시간 설정 켜기 | `w32tm /query /status` |
| AI 서버 (Jetson) | `sudo timedatectl set-ntp true` | 위와 같음 |
| 단말 | 설정 → 날짜 및 시간 → 자동 날짜 및 시간 | 단말 화면 시각 |

사내망에서 외부 시간 서버에 나갈 수 없으면 사내 시간 서버 주소를 `/etc/systemd/timesyncd.conf`의 `NTP=`에 넣는다. 컨테이너는 서버 PC 시계를 그대로 쓰고 한국 시간대(`TZ=Asia/Seoul`)로 로그를 남긴다.

## 5. 백업과 복구

서버가 매일 04시와 시작할 때(그날 백업이 없으면) 백업한다.

- `backup/db/YYYY-MM-DD.db`: DB 사본. 쓰는 중에도 일관되게 뜬다(SQLite `VACUUM INTO`). `BACKUP_KEEP_DAYS`일(기본 14일) 남긴다.
- `backup/faces/`: 등록 얼굴 사진 거울. 새 사진은 복사하고 지운 사진은 같이 지운다. 퇴사나 동의 철회로 지운 얼굴이 백업에 오래 남지 않게 하려는 것이다(동의서 4항).
- 출입 사진과 방문객 사진은 보존 기간이 지나면 지우는 자료라 백업하지 않는다.

백업이 실패해도 출입은 멈추지 않는다. 로그의 `[backup]` 줄로 확인한다. 주 1회 정도 `backup` 폴더를 외부 저장장치에 복사해 두면 서버 PC 고장에도 대비된다. 지금은 사진이 암호화되어 있지 않으므로 외부 저장장치는 BitLocker To Go 등으로 암호화한 것을 쓰고 잠가 둔다.

복구:

    docker compose stop gate-server
    cp /srv/facegate/backup/db/2026-11-04.db /srv/facegate/data/facegate.db
    rm -f /srv/facegate/data/facegate.db-wal /srv/facegate/data/facegate.db-shm
    mkdir -p /srv/facegate/data/files
    cp -r /srv/facegate/backup/faces /srv/facegate/data/files/
    sudo chown -R facegate:facegate /srv/facegate/data   # 컨테이너 계정이 다시 쓸 수 있게
    docker compose start gate-server

복구한 날 이후의 출입 기록과 등록은 사라진다. AI 서버는 얼굴 목록을 서버에서 다시 받으므로 따로 할 일이 없다.
