# 06. 데이터베이스 설계서

버전 0.1 · 2026-10-27 · DBMS: SQLite (기존 엣지 서버와 동일). 게이트 수십 대·직원 수천 명 규모까지 충분.

## 테이블 목록

| 테이블 | 설명 |
|---|---|
| employee | 직원 |
| face_image | 직원 얼굴 등록 사진 |
| nfc_card | 직원 사원증 NFC 스티커 (NTAG 424 DNA) |
| access_group / access_group_gate / access_group_org / access_group_employee / schedule / holiday | 권한 그룹(이름, 시간표), 그룹의 게이트와 구성원(소속, 직원), 시간표(days: 8칸 JSON), 휴일. D-59의 org_gate, employee_gate는 서버 시작 때 그룹으로 옮기고 지움 (D-61) |
| gate | 게이트 |
| terminal | 안드로이드 단말 = 카메라 (단말 번호가 AI 서버의 `device_key`, D-56) |
| access_log | 출입 기록 (판정 1건 = 1행) |
| ai_server_status | AI 서버 상태 |
| admin_user / admin_session / audit_log | 관리자, 로그인 세션, 관리자 작업 이력 |
| visitor_call | 방문객 호출 |
| setting | 설정 값 |

### admin_user / admin_session / audit_log
| 테이블 | 컬럼 |
|---|---|
| admin_user | admin_key PK, login_id UNIQUE, name, password_hash(scrypt), enabled, failed_count, locked_until, must_change_credentials INTEGER NOT NULL DEFAULT 0, created_at |
| admin_session | token_hash PK(SHA-256), admin_key FK, kind(`WEB`/`TERMINAL`), expires_at, created_at |
| audit_log | audit_key PK, admin_key NULL(실패 또는 시작 시 계정 생성), action, target, detail(JSON), created_at |

`must_change_credentials`는 환경 변수로 만든 첫 계정만 1, 기존 계정과 일반 추가 계정과 개발 계정은 0이다. 새 DB 스키마와 기존 DB의 컬럼 추가 마이그레이션을 모두 적용한다. credentials 확인 또는 변경 성공 때 0으로 만든다. `CREDENTIALS_CONFIRM`과 `CREDENTIALS_CHANGE`의 detail은 `{ loginIdChanged, passwordChanged }`이며 입력값을 저장하지 않는다. `admin_session.admin_key`의 `ON DELETE CASCADE`로 개발 계정 삭제 시 웹과 단말 세션도 함께 삭제한다.

### setting
key-value. `duplicate_window_sec`(5), `photo_retention_days`(90), `escort_scope`(`ALL`/`ALLOWED_ONLY`, 기본 ALL), `escort_max`(0=제한 없음, 기본 3), `nfc_max_per_employee`(1~5, 기본 1), `nfc_auth_mode`(`NFC_ONLY`/`FACE_AND_NFC`, 기본 NFC_ONLY), `face_and_nfc_hours`(예: `22:00-07:00`, 비우면 항상), `visitor_call_timeout_sec`(기본 120), `front_phone`(대표 전화번호), `ingest_key_hash`, `terminal_pin_hash`.

기존 DB는 서버 시작 시 없는 컬럼만 추가한다 (`database.ts`의 `MIGRATIONS`).
