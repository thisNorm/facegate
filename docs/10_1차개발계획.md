# 10. 1차 개발 계획

버전 0.1 · 2026-10-28

## 1. 목표

입주(2026년 12월 중순~2027년 1월) 때 **얼굴 출입 + 인사과 원격 개방**만으로 운영할 수 있게 만든다. 범위는 01 문서 3장 "1차" 행을 따른다.

- 끝났다는 기준: 책상 위에서 1차 전 기능 시연 (단말 1대 + AI + 게이트 서버 + 관리자 웹 + 릴레이·LED)
- 기간: 10/29 ~ 11/30 (약 5주). PoC 시험(Task 12)은 보류(D-37)라 1차 개발을 앞당겨 시작한다
- 이후: 12/1~12/14 현장 설치·시범(01 문서 3단계)

## 4. 하위 프로젝트별 내용

### P1. 관리자 계정·세션·작업 이력
- 관리자 계정 테이블: 아이디, 이름, 비밀번호 해시(`node:crypto` scrypt, 추가 의존성 없음), 사용 여부. 역할은 1종류(FR-A-01)
- 로그인 → 세션 쿠키(`HttpOnly`, `SameSite=Strict`, 8시간 만료, 서버 DB 보관). 로그아웃·만료 시 즉시 무효
- 로그인 5회 실패 시 10분 잠금
- 단말 관리자 모드(FR-T-07)용: 같은 계정으로 로그인해 **짧은 수명(10분) 단말 토큰** 발급 (아이디·비밀번호만, QR 로그인은 하지 않음 D-42)
- 작업 이력(FR-A-11): 누가·언제·무엇을·대상. 직원 변경, 사진 등록·삭제, 원격 개방, 설정 변경, 키 발급, 로그인 성공·실패
- 첫 관리자는 관리자 웹 초기 설정 화면(A-00)에서 만든다(D-43). `X-Admin-Key`는 관리자 API에서 제거
- 끝 기준: 계정 없이 관리자 API 401, 로그인 후 200, 모든 변경이 작업 이력에 남음 (통합 테스트)

### P2. 관리자 API 완성
- 직원: 목록·검색·상세·수정·퇴사(즉시 차단 + 얼굴 사진 삭제, 트랜잭션), 사진 개별 추가·삭제, 사진마다 등록 경로·등록자·일시(FR-A-03-2)
- 출입 기록: 기간·이름·게이트·결과·인증 수단 필터, 사진 보기, 엑셀(CSV, UTF-8 BOM) 내보내기
- 원격 개방(FR-S-10, FR-A-09): 사유 필수(방문객 / 직원 인증 불가 / 기타), 기본은 방문객. 직원은 얼굴 인식 실패 시 NFC를 우선 사용하고 두 수단을 사용할 수 없는 경우 관리자 예외 개방한다. 기존 API 사유 값 `RECOGNITION_FAILED`는 유지한다. 방문객이면 이름·회사·방문 대상. 출입 기록에 인증 수단 `REMOTE`. 실제 NFC 인증은 1.5차 범위(D-26)를 유지한다
- 상태(FR-A-08, FR-S-09): 게이트·단말 연결·AI 온라인(3분 미수신 → 오프라인)·단말별 AI 영상 수신(`rtsp_ok`)
- 설정(A-10): 중복 개방 간격, 사진 보존 기간(7~365일, 기본 90일), 인제스트 키(완료)
- 사진 보존 자동 삭제(NFR-10): 매일 03시, 기간 지난 사진 파일 삭제, 기록 행은 유지
- API 계약은 04 문서 IF-8

### P3. 관리자 웹
- 스택: React + Vite + TypeScript, `apps/admin-web`. 빌드 결과를 게이트 서버가 정적 파일로 제공(같은 출처 → 쿠키 세션 그대로)
- 화면(05 문서): 로그인, 현황(A-02, D-44), 직원 목록·상세·등록, 사진 등록(잘 촬영된 기존 파일 업로드, `WEB_UPLOAD`, D-48), 출입 기록, 게이트 관리(조회), 단말 관리(토큰·QR), 설정, 작업 이력, **빠른 개방(A-14)**
- 끝 기준: 인사과 담당자가 마우스만으로 직원 등록 → 기존 사진 파일 업로드 → 출입 확인 → 원격 개방까지 할 수 있음
- 추가 요구(D-49): 게이트 2대, 단말 2대 기준으로 관리자 웹 현황에 두 단말 영상을 2열로 고정해 동시에 표시하고 각 영상 가까이에 같은 게이트의 1회 개방 폼을 둔다. 모달과 게이트 선택·전환은 없으며 사유·방문객 입력과 대기·성공·실패 결과를 게이트별로 독립 유지한다. 불필요한 메뉴·테두리와 미지원 닫기·재시작·NFC 버튼은 추가하지 않는다. 최근 출입 표와 오늘 원격 개방 이력은 아래에 둔다. 성공 문구는 "개방 신호를 보냈습니다"이며 실제 개폐 센서 없는 열림/닫힘 표시는 하지 않는다. RTSP/TCP를 서버 FFmpeg에서 JPEG 장면(5fps, 가로 960px)으로 변환하고 웹이 0.5초마다 최근 장면을 받는다(D-53). 2초보다 오래되거나 받지 못한 장면은 감추고 끊김을 표시한다. 2차 방문객 호출의 정지 사진·자동 알림, 전체 앱 화면 미러링과 음성 통화는 미구현이며 별도 범위. 실제 단말 영상과 실물 릴레이 동작은 미검증

### P4. 단말 앱 1차
- (앞당겨 끝남, D-57) 단말 연결: 미연결 화면, QR·번호 연결, 연결 해제 복귀. 관리자 웹 게이트 화면(A-07, A-09)
- 대기 화면(로고·시각·안내), 허가·거부 화면 디자인(T-01~T-03), 효과음(권장)
- 서버 끊김 시 "점검 중 — 인사과 문의"(FR-T-05)
- 30초마다 상태 보고: fps, 접속 수, 온도(FR-T-12) → WebSocket 메시지
- 관리자 모드(FR-T-07): 모서리 5회 탭 → 아이디·비밀번호 → 현장 기능(서버 주소·게이트 번호, 얼굴 등록)
- 얼굴 등록 모드(FR-T-18): 사번 검색 → 정면 1, 정면 2, 좌측, 우측, 상향, 하향의 6장 → `source: 'TERMINAL'`로 업로드, 촬영 중 판정 화면 멈춤. 웹과 같은 관리자 계정·관리자 API·작업 이력 사용(D-31, D-48)
- 키오스크(FR-T-06): Device Owner + Lock Task, 부팅 자동 실행. PoC의 길게 누르기 설정 대화상자는 제거
- RTSP 비밀번호가 logcat에 남는 문제(RootEncoder 로그) 처리

### P5. 얼굴 사진 품질 검사 (정할 것 ①에 따라)
- 검사 항목: 얼굴 1개만, 최소 크기, 흐림·역광, 정면 각도(FR-A-03-1). 실패 시 사유 표시 후 거부
- 1차 등록 경로(기존 파일 업로드 `WEB_UPLOAD`·단말 관리자 모드 촬영 `TERMINAL`)가 같은 검사를 거치도록 서버에서 검사. 동의 확인·1인 최대 10장 규칙 유지. 기존 `WEBCAM` 값은 서버 API·DB 호환용으로 유지하고, 2차 `SELF`·`BULK`도 같은 검사 적용

### P6. 운영·배포
- HTTPS: 사내 인증서(정할 것 ③). 단말 ws:// → wss://, 관리자 웹 https
- Docker 이미지(게이트 서버 + 관리자 웹 정적 파일), `docker compose`로 실행, DB·사진 볼륨
- NTP 시각 동기화 확인, DB 백업(매일, SQLite `VACUUM INTO`)
- 원격 관리 서버 Heartbeat(FR-S-11, 권장): 시간이 남으면
