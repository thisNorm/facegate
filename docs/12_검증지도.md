# 12. 검증 지도

버전 0.1 · 2026-11-04

기능마다 어디서 확인하고 무엇이 나와야 하며 증거가 어디 있는지 적는다. 현장 설치 전 점검표로 쓴다. 기능을 바꾸면 이 표의 증거와 상태를 같이 고친다.

상태: **자동** 테스트가 매번 확인 / **화면** 사람이나 브라우저로 직접 확인(날짜) / **미확인** 아직 증거 없음 / **미구현**

테스트 실행: `services/gate-server`에서 `npm test`, `apps/admin-web`에서 `npx vitest run`, `apps/terminal-android`에서 `gradlew testDebugUnitTest`.

## 3. 남은 위험

- 실물 게이트 릴레이로 문이 열리는지 아직 모른다 (F-06). 게이트 업체 답변(Q-03, Q-04) 뒤 확인.
- 얼굴 사진은 아직 암호화 없이 저장된다 (F-21). 서버 PC가 공용이라 디스크 전체 암호화는 기본으로 하지 않고, 서버가 사진을 직접 암호화하는 방식을 다음에 만든다. 그때까지는 폴더 권한(F-20)과 암호화한 외부 백업 저장장치로만 막는다.
- Docker 이미지가 실제로 만들어지는지 모른다 (F-15). 서버 PC에서 처음 띄울 때 확인.
- 단말에서 관리자 로그인 뒤 실제 등록과 동의 흐름은 사람이 한 번 해 봐야 한다 (F-03).
- 핸드폰으로 열기는 실제 아이폰과 안드로이드로 대 봐야 한다 (F-22). 아이폰이 안드로이드 단말의 태그 흉내를 잘 읽는지는 기종마다 다를 수 있어 QR을 함께 둔다. 운영에서는 회사 도메인 정식 인증서가 있어야 핸드폰에 경고가 뜨지 않는다.
- 단말 안 얼굴 인식(F-23)의 두 모델은 학습 가중치가 비상업 연구용이다. 운영 전에 허가를 받거나 바꿔야 한다. 기준값 0.40에서 역광의 흐린 장면 11장 중 4장이 '모르는 사람'(0.33~0.40)이었다. 실제로 서서 재 보고 정한다.
- 화면 전체를 브라우저로 자동 확인하는 시험은 없다. 화면 배치 문제는 사람이 본다.
