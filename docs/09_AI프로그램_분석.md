## 1. 현재 구조

```
[RTSP 카메라 ×최대 4] → 초당 4장 샘플링 → 2×2 격자(640×640, 카메라당 320×320 칸)
   → SCRFD-10G 얼굴 검출 (TensorRT FP16)
   → 품질 필터: 정면(랜드마크), 아래로 30° 넘게 숙임 제외, 흐림(라플라시안 60 미만) 제외
   → FaceMoE BRIAR 512차원 특징 (TensorRT FP16) → 등록 얼굴과 코사인 유사도 ≥ 0.4 → 직원
   → 같은 사람·같은 카메라로 4번 일치하면 "확정" → appear 파일(.txt + 사진) 저장
[감독 프로세스] 2초마다 로그 폴더 확인 → POST /face/appear, /face/disappear
               60초마다 /status, /rtsp, /face/dataset
```

| 항목 | 현재 값 | 설정 |
|---|---|---|
| 샘플링 | 초당 4장 | `FRAME_DETECT_PER_SECOND: 4` |
| 확정 조건 | 같은 사람 4회 일치 | `EVENT_CONFIRMATION_MATCHES: 4` |
| 직원 판정 기준 | 코사인 유사도 0.4 이상 | `DISTANCE_THRESHOLD: 0.4` |
| 사라짐 판정 | 20초 동안 안 보이면 disappear | `WAIT_TIME_SEC: 20` |
| appear 전송 | 2초마다 폴더 확인 후 전송 | 감독 프로세스 `interval_log` |
| 데이터셋 동기화 | 60초마다, 바뀐 경우만 다시 받음 | `interval_facedataset` |
| 카메라 수 | 2×2 격자 = 최대 4대 | `GRID_SHAPE: [2, 2]` |

## 2. 미결 질문 답변

| 번호 | 질문 | 코드에서 확인한 답 |
|---|---|---|
| **Q-12** | 미등록으로 보낸 뒤 직원으로 인식되면 다시 보내나? | **보냅니다.** 직원 판정과 미등록 판정을 따로 셉니다. 처음 몇 장이 미등록이어도, 이후 직원으로 4번 일치하면 직원 appear가 따로 나갑니다. 단, **미등록 appear도 먼저 나갈 수 있습니다** (미등록으로 먼저 4번 일치한 경우). → 게이트 서버는 미등록 appear를 받아도 조용히 기록만 하고, 같은 단말에서 곧 직원 appear가 오면 그걸로 엽니다 (05 문서 T-03 "조용히" 규칙과 일치) |
| **Q-12** | appear는 언제 나가나? | 확정(4회 일치) 순간 파일 저장 → **최대 2초 뒤** 전송. 확정까지 초당 4장 기준 최소 약 0.75~1초 |
| Q-10 | 라이브니스(사진·영상 위조 방지)? | **없습니다.** 정면·숙임·흐림 필터만 있고 위조 판별은 없음 |
| Q-13 | 데이터셋 재동기화 주기? | **60초.** 신규 등록·퇴사는 최대 1분 뒤 반영 (퇴사자는 게이트 서버가 재직 상태로 먼저 막으므로 문제없음) |
| Q-16 | 지연·용량? | 확정까지 ~1초 + 전송 대기 최대 2초 = **현재 최악 약 3초**. 카메라 최대 4대 (1080p를 320×320으로 줄여 처리) |
| Q-17 | 여러 명 동시? | 사람별로 따로 추적·전송. 같은 사람이 20초 안에 다시 나타나면 **새 appear가 나가지 않음** |
| Q-18 | 등록 사진 장수 | 1인 여러 장 지원 (데이터셋 폴더에 사람별 이미지) |
| Q-21 | RTSP 형식 | OpenCV로 읽는 일반 RTSP. 1080p H.264 가능 (기존 카메라도 1080p) |

## 3. 게이트용으로 바꿔야 할 것

> D-20: 게이트용 AI는 현행 코드를 가져와 수정합니다. 아래 표가 **AI 변경 요구사항**이며, AI 제작자에게 그대로 전달하거나 직접 수정할 때 체크리스트로 씁니다. 가져올 때는 기존 설정·데이터(`data/base_imageset`, `unknown_data_*.json`, 로그)는 빼고 코드·모델만 가져옵니다 (모델은 4장 라이선스 확인 후).

현재 설정은 "현장에 누가 왔다 갔는지" 기록용이라, 게이트처럼 **1초 안에 문을 열어야 하는 용도**에는 그대로 쓰기 어렵습니다.

| 번호 | 문제 | 변경안 | 우선순위 |
|---|---|---|---|
| AI-01 | 전송이 2초마다 폴더를 확인하는 방식 → 최대 2초 지연 | 확정 즉시 HTTP 전송 (파일 저장은 비동기로 뒤에) | **필수** |
| AI-02 | 초당 4장 × 4회 확정 → 최소 ~1초 | 게이트 설정: **초당 10장, 2~3회 확정** (PoC에서 오인식과 비교해 결정) | **필수** |
| AI-03 | 같은 사람 20초 안 재등장 시 appear 없음 → 열림 실패 후 다시 서도 안 열림 | 게이트 설정: `WAIT_TIME_SEC` **3~5초** | **필수** |
| AI-04 | 카메라당 320×320 칸 → 게이트에선 얼굴이 크니 문제없지만 멀리 있는 사람까지 잡음 | **얼굴 최소 크기** 조건 추가 (가까운 사람만 판정, 지나가는 사람 무시) | **필수** |
| AI-05 | 라이브니스 없음 → 휴대폰 사진으로 열릴 수 있음 | 위조 방지 모델 추가 검토 (예: 무음 라이브니스 모델) 또는 **NFC 병행 정책으로 위험 수용** 결정 | 결정 필요 (Q-33) |
| AI-06 | 유사도 기준 0.4 (기존 기준) | 게이트는 오인식(남이 열림)이 더 치명적 → 직원 사진으로 기준값 다시 측정 | 필수 (PoC) |
| AI-07 | 기존 설정(`FARM_ID: site`, `LABEL_NAME` 등)이 코드 설정에 섞여 있음 | 게이트용 설정 파일 분리 (`conf_api.gate.yaml`) | 권장 |
| AI-08 | 프로그램 복사본이 여러 개(`Face_Recognition_API`, `(3)`, `4`, `(copy)`, `_tensorRT`, `_tensorRT_main`) | 게이트용은 git 저장소 하나에서 관리 | 권장 |

## 4. 라이선스 주의 (확인 필요, Q-34)

| 구성 요소 | 확인한 것 | 주의 |
|---|---|---|
| FaceMoE 코드 | MIT 라이선스 | 코드는 사용 가능 |
| FaceMoE 가중치 (`briar_full`) | BRIAR 데이터로 미세조정한 가중치 | BRIAR 데이터셋은 연구용 제공 데이터로 알려져 있음 → **상업 시설 출입 용도로 써도 되는지 확인 필요** |
| SCRFD-10G 검출기 (`det_10g`) | InsightFace 계열 모델로 보임 | InsightFace 사전학습 모델은 **비상업 연구용** 조건으로 배포됨 → 확인 필요 |
| LVFace 가중치 (현재 미사용) | 저장소 문서에 "비상업 연구용 제한" 명시 | 게이트에 쓰지 않음 |

회사 사옥 출입은 상업적 이용으로 볼 여지가 있으므로, 정식 운영 전에 가중치 사용 조건을 확인하거나 상업 사용이 허용된 모델로 바꿔야 합니다. 이 판단은 법적 검토가 필요하며 이 문서는 확인 필요 사항만 정리한 것입니다.
