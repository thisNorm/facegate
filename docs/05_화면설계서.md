# 05. 화면 설계서

버전 0.1 · 2026-10-27

## 1. 게이트 단말 앱 (Android, 세로 8~10인치)

참고: Suprema BioStation 3, Hikvision MinMoe, ZKTeco SpeedFace의 공통 패턴. 한 화면 안에서 상태만 바뀌는 구조이며, 결과는 **1초 안에 한눈에** 보여야 합니다.

### T-01 대기 (안 B: 카메라 미리보기 있음)
```
┌──────────────────────┐
│ [회사 로고]   08:51   │
│ ┌──────────────────┐ │
│ │  카메라 미리보기   │ │
│ │   ╭────────╮     │ │
│ │   │ 얼굴틀 │     │ │
│ │   ╰────────╯     │ │
│ └──────────────────┘ │
│    정면을 봐주세요     │
│ 인식이 안 되면 사원증을 ▼ │
│     [ 방문객 호출 ]     │
│ 공지: 오늘 18시 소방점검 │
└──────────────────────┘
          [NFC 안테나 위치]
```
- 화면 아래쪽에 NFC 안테나 위치를 가리키는 표시 (단말마다 안테나 위치가 다르므로 기기 선정 후 확정). 단말 테두리에 "사원증 대는 곳" 표시 스티커 권장.
- 미리보기는 거울처럼 좌우 반전, 얼굴 가이드 틀 표시 (사람이 스스로 위치를 맞추게 함).
- 미리보기는 화면 표시용일 뿐, 인식 판단은 AI 서버가 합니다. 단말은 "얼굴 인식 중" 같은 판단을 하지 않습니다.
- 송출이 끊기면 미리보기 위에 "점검 중" 표시 (T-04).
- 다크 배경 (로비 조명에서 눈부심 방지).

### T-02 허가 (+ 손님 동반)
```
┌──────────────────────┐
│██████ 초록 ███████████│
│        ✓             │
│      홍길동           │
│      개발팀           │
│     환영합니다         │
└──────────────────────┘
```
- 화면 아래 **[손님 동반]** 버튼을 5초간 표시. 누르면 인원 선택(1·2·3) → "손님 2명 — 차례로 통과하세요".
- 버튼을 안 누르면 1.5초 뒤 T-01로 복귀 (동반 버튼만 5초까지 남음). 다음 사람 결과가 오면 즉시 덮어씀.
- 효과음 "띵".

### T-08 방문객 호출
```
┌──────────────────────┐
│     방문객 호출        │
│   담당자를 부르는 중…   │
│      ◐ 0:42          │
│                      │
│        [취소]         │
└──────────────────────┘
```
- 누르는 순간 단말 카메라로 사진 1장 → 인사과 관리자 웹 알림.
- 결과: "곧 열립니다 — 게이트로 들어오세요"(초록) / "죄송합니다, 입장이 어렵습니다"(회색) / 무응답(기본 2분) "만나실 직원에게 연락해 주세요 ☎ 대표번호".

### T-02-1 2단계 인증 대기 (`얼굴+NFC` 시간대)
- 얼굴만 인식됨 → 파란 화면 "홍길동님, 사원증을 대주세요" (10초 카운트다운)
- 사원증만 태그됨 → 파란 화면 "얼굴을 카메라에 봐주세요" (10초 카운트다운)
- 10초 안에 나머지가 안 오면 T-01로 복귀 (기록: 2단계 인증 미완료)

### T-03 거부
```
┌──────────────────────┐
│██████ 빨강 ███████████│
│        ✕             │
│   등록되지 않은 얼굴    │
│   인사과에 문의하세요    │
└──────────────────────┘
```
- 사유 문구: `UNREGISTERED` "등록되지 않은 얼굴 — 사원증을 대주세요" / `DENIED_CARD_UNKNOWN` "등록되지 않은 사원증" / `DENIED_CARD_LOST` "사용이 정지된 사원증" / `DENIED_CARD_FORGED`·`DENIED_CARD_REPLAY` "사용할 수 없는 사원증 — 인사과 문의" (관리자 경보) / 그 외 `DENIED_*` "출입 권한이 없습니다" / `GATE_ERROR` "게이트 오류 — 잠시 후 다시".
- 미등록 얼굴 거부 화면은 **조용히** 처리 (경고음 없이 작게): 지나가는 사람·뒷사람이 비칠 때마다 빨간 화면이 뜨면 혼란스럽기 때문. 카드 거부는 경고음 포함.
- 이름 표시 안 함. 2초 뒤 T-01 복귀.

### T-04 점검 중
| 상황 | 화면 | NFC |
|---|---|---|
| AI 서버 오프라인 / 단말 송출 오류 | 주황 띠 "얼굴인식 점검 중 — 사원증을 대주세요" | **사용 가능** |
| 게이트 서버 연결 끊김 | 회색 화면 "점검 중 — 인사과에 문의하세요" | 사용 불가 |
| 게이트(릴레이) 오류 | 회색 화면 "게이트 점검 중" | 사용 불가 |

### T-00 단말 미연결 화면 (D-57)
- 연결 정보가 없을 때의 첫 화면. 가로 1280×800, 어두운 배경, 누르는 버튼 없음.
- 왼쪽: 제목 "단말 연결이 필요합니다", 순서 세 줄, 아래 상자에 **단말 주소**와 **연결 번호**(6자리, 3자리씩 띄움, 10분마다 바뀜).
- 오른쪽: 카메라 미리보기 위 QR 맞춤 사각형, 상태 글자(QR을 찾는 중, 연결 중, 실패 사유, "{게이트}에 연결되었습니다").
- 연결되면 2초 뒤 판정·송출 화면. 관리자 웹에서 연결 해제하면 이 화면으로 돌아온다. 연결된 뒤 화면을 길게 누르면 연결 정보(서버, 게이트, 단말 번호)와 다시 연결.

### T-05 단말 관리자 모드 (숨김, D-31)
- 진입: 화면 오른쪽 위 모서리 5회 연속 탭 → **웹과 같은 관리자 계정으로 로그인** (아이디·비밀번호. QR 로그인은 하지 않음, D-42).
- 웹과 같은 화면 구성·용어를 쓰되, 단말에서는 현장 기능만: 얼굴 촬영 등록, NFC 발급, 이 게이트 열기, 이 게이트 최근 기록 20건, 단말 상태. 직원 정보 수정·시스템 설정은 웹에서만.
- 로그인 중에는 화면 위에 "관리자: 홍길동 · 2:45 후 자동 로그아웃" 표시. 3분 무조작 시 로그아웃 후 T-01.
- 항목: **얼굴 등록(T-06)**, **사원증 NFC 발급(T-07)**, 연결 정보 보기와 다시 연결(서버 주소·게이트·토큰은 입력하지 않음, D-57), 앱 버전, **송출 상태(해상도·fps·접속 수·온도)**.

### T-06 얼굴 등록 모드 (관리자 전용)
```
┌──────────────────────┐
│ 얼굴 등록   [취소]     │
│ 사번 검색: [ 2024013 ] │
│ 홍길동 · 개발팀        │
│ ┌──────────────────┐ │
│ │   ╭────────╮     │ │
│ │   │ 얼굴틀 │     │ │
│ │   ╰────────╯     │ │
│ └──────────────────┘ │
│ 2/6장 촬영            │
│ "고개를 살짝 왼쪽으로"  │
└──────────────────────┘
```
- 진입: T-05 관리자 설정 → "얼굴 등록". 사용 중에는 이 단말의 출입 판정 화면을 멈추고 상단에 "등록 중" 표시 (게이트 개방은 서버가 계속 처리).
- 신규 등록은 정면 1, 정면 2, 좌측, 우측, 상향, 하향의 6장을 순서대로 촬영한다. 1장 이상 찍으면 등록할 수 있다(D-54).
- 생체정보 동의가 없는 직원은 "동의 필요 — 관리자 웹에서 동의 처리" 안내 후 촬영 불가.
- 촬영 직후 서버 품질 검사 결과를 장마다 표시 (통과 ✓ / 다시 찍기).
- 등록 경로는 `TERMINAL`. 웹과 같은 관리자 계정·관리자 API·작업 이력을 사용한다(D-31, D-48).
- 10분 동안 조작이 없으면 자동 종료.

### T-07 사원증 NFC 발급 (관리자 전용)
```
┌──────────────────────┐
│ 사원증 NFC 발급 [취소] │
│ 사번 검색: [ 2024013 ] │
│ 홍길동 · 개발팀        │
│ 현재 스티커: 없음       │
│                      │
│   스티커 붙인 사원증을   │
│    여기에 대주세요 ▼    │
│  ▓▓▓▓▓▓▓░░░  설정 중…  │
│  떼지 마세요 (약 2초)   │
└──────────────────────┘
```
- 진행: 대기 → 설정 중(진행 막대, "떼지 마세요") → 확인 읽기 → "발급 완료 ✓" 또는 "실패 — 다시 대주세요".
- 최대 장수에 이미 도달한 직원이면 "가장 오래된 스티커(발급일)가 정지됩니다" 확인 후 진행 (FR-N-17).
- 다른 직원의 스티커면 "이미 ○○○님에게 발급된 스티커" 표시 후 중단 (이름은 관리자에게만 보임).
- 발급 중에는 이 단말의 출입 NFC 판정을 멈춤.

## 2. 웹 관리자 (PC 브라우저, 데스크톱 전용)

사용자가 제공한 관리자 웹 초안을 기준으로 짙은 청남색 사이드바, 흰 헤더와 작업 영역, 밝은 청회색 바탕, 파란 주요 버튼을 사용합니다. 현황의 두 단말 영상과 각자의 개방 입력을 나란히 두고 아래에 기록 표를 배치합니다. 세부 색상과 간격은 `apps/admin-web/DESIGN.md`를 따릅니다.

| ID | 화면 | 주요 요소 |
|---|---|---|
| A-00 | 계정 정보 확인(첫 로그인) | 로그인 또는 세션 확인 응답의 `mustChangeCredentials`가 참이면 표시. 제목은 "계정 정보 확인". 아이디, 현재 비밀번호, 새 비밀번호(선택), 새 비밀번호 확인. [변경하고 계속] 또는 [그대로 쓰기]. 어느 쪽이든 현재 비밀번호 필수. 완료하면 표시를 지우고 현황으로 이동 (D-45) |
| A-01 | 로그인 | 아이디, 비밀번호. 5회 실패 시 "10분 뒤 다시 시도" 안내 |
| A-02 | 현황 (첫 화면) | **등록된 모든 게이트**를 대상으로 화면 폭에 맞춰 영상과 개방 영역을 배치(A-14, D-49, D-52). 한 페이지에 최대 4대를 표시하고 5대 이상은 이전/다음 페이지로 탐색한다. 등록 대수 제한은 두지 않는다. 각 영역에 게이트 이름, 단말 연결, 영상(게이트 서버가 받는 단말 영상) 연결, 얼굴인식(AI가 보고한 이 게이트 단말 영상 수신) 상태(D-55), 0.5초마다 새로 받는 단말 영상 장면(2초보다 오래되면 감추고 "영상 끊김" 표시, D-53)과 해당 게이트의 **1회 개방** 버튼, 독립된 사유·방문객 입력과 결과를 둔다. 모달과 불필요한 테두리 없음. 정상은 회색, 문제가 있는 상태만 강조. 맨 위 한 줄에 얼굴인식 서버 상태(마지막 응답 시각). 아래에 최근 출입 표(시각, 게이트, 이름, 결과)와 오늘 원격 개방 이력, 미등록과 오류만 강조. NFC 위조 경보는 1.5차. **화면에 숫자 카드, 차트, 장식 아이콘, 그라데이션, 가운뎃점 구분자 쓰지 않음** (D-44) |
| A-03 | 직원 목록 | 검색(이름·사번·부서), 상태 필터(재직/퇴사/얼굴 미등록), 엑셀 일괄 등록 |
| A-04 | 직원 상세·등록 | 기본 정보, 권한 그룹, **손님 동반 가능 체크**(설정이 "허용된 직원만"일 때), **얼굴 사진 칸(최대 10장)**: 기존 파일 업로드(`WEB_UPLOAD`), 단말 촬영 사진(`TERMINAL`) 조회·개별 삭제, 품질 경고(흐림·여러 얼굴·너무 작음), 생체정보 동의 체크(동의일 저장), **NFC 스티커 칸**(상태·발급일·마지막 사용, 분실 정지·회수 버튼 / 발급은 단말 T-07에서), 퇴사 처리 버튼 |
| A-05 | 출입 기록 | 기간·게이트·결과·이름·**인증 수단(얼굴/NFC/원격)** 필터, 행마다 촬영 사진 썸네일, 엑셀 내보내기 |
| A-06 | 미등록자 감지 | 사진 그리드, 날짜·게이트 |
| A-07 | 게이트 (D-57) | 게이트 표(이름, 개폐기, 단말별 연결·IP·앱 버전·마지막 접속), **게이트 추가·수정·삭제**(개폐기: 가짜 또는 릴레이 IP·포트·유닛·코일·펄스, 단말이 있으면 삭제 불가), **개방 시험**, 단말 **이름 바꾸기·옮기기·연결 해제** |
| A-08 | 출입 권한 (D-61) | 탭: 권한 그룹(이름, 시간표, 층별 게이트, 구성원 소속과 직원) / 시간표(요일과 휴일마다 시간 한 구간) / 휴일(날짜, 이름) / 소속(추가, 이름 변경, 삭제). 직원 상세에는 권한 그룹(소속으로 받은 그룹은 잠금)과 다닐 수 있는 게이트 |
| A-09 | 단말 추가 (A-07 안의 창, D-57) | 위: 10분 1회용 QR, 남은 시간, "단말 카메라에서 30~50cm". 아래 "QR을 쓸 수 없으면": 단말 주소, 연결 번호 입력 후 연결. 어느 쪽이든 단말이 생기면 창이 닫힘 |
| A-10 | 설정 | 중복 개방 간격, 사진 보존 기간, **손님 동반 대상·최대 인원**, **NFC 스티커 1인 최대 장수**, **NFC 인증 방식(NFC만 / 얼굴+NFC, 적용 시간대)**, **방문객 호출 무응답 시간·대표 전화번호**, AI 연동 키 발급(발급 시 1회 전체 표시, 이후 마지막 4자리·발급 시각만 표시), 관리자 계정 |
| A-11 | 작업 이력 | 관리자, 시각, 작업, 대상 |
| A-12 | 셀프 등록 승인 | 직원이 올린 사진 목록, 기존 사진과 나란히 비교, 승인/거절(사유) |
| A-14 | 빠른 개방, 단말 영상 확인(D-49). 방문객 호출 알림은 2차 | 현황에 **등록된 게이트 수에 맞춰 단말 영상과 1회 개방 폼을 배치**한다. 한 페이지에 최대 4대를 표시하며 현재 페이지의 영상만 연결한다. 페이지를 떠나면 중계를 해제하되 각 폼의 입력과 요청 결과, 카메라 선택은 유지한다. 모달은 두지 않는다. 서버는 동시에 8카메라까지 캡처하므로 두 관리자가 서로 다른 페이지를 봐도 영상이 나온다(D-52, D-53). 사유(방문객/직원 인증 불가/기타, D-51), 방문객 이름·회사, 메모와 요청 대기·성공·실패 결과는 게이트별로 독립 유지. 영상은 0.5초마다 최근 장면 한 장을 받아 보여주며 "영상 확인 중", "실시간 영상", "영상 끊김"을 구분한다. 받지 못했거나 2초보다 오래된 장면은 감추고, 장면이 다시 오면 저절로 이어서 보여준다. 숨은 탭에서는 요청을 멈춘다. 성공은 "개방 신호를 보냈습니다"로 알리고 실제 개폐 센서가 없는 열림/닫힘은 표시하지 않음. 미지원 닫기·재시작·NFC 버튼은 추가하지 않음. 호출 알림(소리·로비 사진·열기/거절)과 음성은 미구현이며 별도 범위 |
| A-13 | 직원 셀프 업로드 (직원용) | 사번·비밀번호 로그인, 동의서 확인, 사진 업로드, 승인 상태 확인 |

### 1차 출입 기록 (A-05, A-06)

- 시작일과 종료일은 서버 수신 시각 기준 한국 날짜이며, 처음에는 오늘을 조회한다. 게이트, 결과, 인증 수단, 이름·사번·방문객 이름으로 검색한다. 1차 인증 수단은 얼굴과 원격이며 NFC는 1.5차에 추가한다.
- A-06은 같은 표의 [미등록만] 바로가기로 제공한다. 기록은 최신순으로 50건씩 조회하고 [더 보기]로 이전 기록을 추가한다. 불러오는 중, 검색 결과 없음, 오류를 구분하며 오류 시 재시도할 수 있다.
- 사진 썸네일은 키보드로도 확대할 수 있다. 전체 사진이 있으면 전체 사진을, 얼굴 사진만 있으면 얼굴 사진을 표시한다. 사진이 없거나 파일을 불러올 수 없으면 상태를 글자로 알린다.
- [CSV 내려받기]는 마지막으로 적용한 검색 조건을 사용하고 페이지 커서는 포함하지 않는다. 아직 검색하지 않은 입력 변경은 반영하지 않는다. 서버의 최대 50,000행 제한을 따르며 잘림 표시는 별도 제공하지 않는다.

### 1차 설정과 작업 이력 (A-10, A-11)

- 출입 설정은 중복 개방 간격 1~60초와 출입 사진 보존 기간 7~365일을 저장한다. 조회 오류는 다시 불러올 수 있고, 저장 실패 시 입력을 유지한다.
- AI 연동 키는 평소 끝 4자리와 발급 시각만 표시한다. 현재 키 상태를 확인한 뒤 새 키를 발급하며, 기존 키가 있으면 즉시 무효화된다는 확인을 받는다. 재발급을 시작하면 이전 전체 키를 숨긴다. 새 키 전체는 발급한 화면에서만 보이고 화면을 떠나면 지운다. 발급 응답 오류 시 결과가 불확실함을 알리고 현재 키 정보를 다시 조회하며, 자동 재발급하지 않는다.
- 관리자 계정은 목록, 추가, 다른 계정의 사용 중지와 다시 사용을 제공한다. 본인 계정의 상태 변경 버튼은 표시하지 않는다. 상태 변경 응답에 오류가 있어도 목록을 다시 조회해 실제 상태를 확인한다. 개발용 예약 아이디로 계정을 추가할 수 없으면 그 사유를 안내한다.
- 내 비밀번호 변경은 현재 비밀번호와 새 비밀번호 확인을 받는다. 새 비밀번호는 빈 문자열만 거절하고 공백을 제거하지 않는다. 제출 시 표시된 비밀번호를 다시 가리며, 실패하면 입력을 유지하고 성공하면 비운다. 현재 화면의 세션 만료는 로그인 화면으로 이동하며, 이미 떠난 화면의 지연 응답은 새 로그인을 종료시키지 않는다.
- 쓰기 요청 중에는 해당 입력과 버튼을 잠가 중복 요청을 막는다. 기존 로그인 세션과 교차 사이트 요청 차단 계약을 유지한다.
- 작업 이력은 최근 200건을 시각, 관리자, 작업, 대상, 내용의 표로 표시한다. 작업명은 한글로, 상세 값은 일반 텍스트로 표시한다. 불러오는 중, 빈 결과, 오류를 구분하고 조회 오류는 재시도할 수 있다.

### 로그인 흐름

첫 방문은 `GET /api/admin/auth/me`로 확인한다. 401이면 A-01 로그인, 로그인 뒤 `mustChangeCredentials`가 참이면 A-00 계정 정보 확인, 거짓이면 업무 화면으로 이동한다. 새 비밀번호 칸을 비우면 기존 비밀번호를 유지하고 필드를 보내지 않는다. [그대로 쓰기]는 아이디와 새 비밀번호를 보내지 않고 현재 비밀번호만 보낸다.

웹은 `appEnv`와 관계없이 개발 모드 표시를 하지 않는다. 개발 모드는 서버 시작 경고로만 알린다 (D-46). 관리자 추가와 비밀번호 변경은 빈 문자열만 거절하며 길이 제한은 없다. 로그인 5회 실패 시 10분 잠금은 유지한다 (D-47).

### 비밀번호 입력 칸 (A-00, A-01, 비밀번호 변경, 단말 T-05 공통)
- 입력값은 `●●●●`로 가림(`type="password"`)
- 칸 오른쪽 안에 **눈 아이콘(SVG)** 버튼: 누르면 글자가 보이고(아이콘이 눈에 빗금 친 모양으로 바뀜), 다시 누르면 가림. 버튼에 `aria-label`("비밀번호 보기" / "비밀번호 숨기기")
- 보기 상태는 화면을 떠나거나 제출하면 다시 가림

### 얼굴 등록 흐름 (A-04)
1차 등록 경로 2가지(D-48): 관리자 웹에서 잘 촬영된 기존 파일 업로드(`WEB_UPLOAD`) / 게이트 단말 관리자 모드 촬영(T-06, `TERMINAL`). 관리자 PC에는 웹캠이 없습니다. 직원 셀프 업로드(A-13, 승인 A-12, `SELF`)와 엑셀+ZIP 일괄 등록(`BULK`)은 2차입니다. 동의 확인과 품질 검사는 모든 경로에 공통 적용합니다.

1. 직원 선택 → 생체정보 수집·이용 동의 확인 (미동의면 사진 칸 비활성)
2. 신규 등록은 **정면 1, 정면 2, 좌측, 우측, 상향, 하향** 칸에 한 장씩 등록한다. 웹은 같은 크기의 여섯 칸을 유지하고 미동의 상태에서는 파일 선택을 비활성화한다. **1장 이상이면 등록할 수 있다**(여러 방향을 채울수록 인식이 잘 된다는 안내 표시, D-54). 서버는 신규 등록 JPEG 1~6장과 중복 여부를 검증하며 촬영 방향은 등록자가 확인한다. 기존 직원의 사진 추가·개별 삭제와 최대 10장 보관 규칙은 유지한다
3. 저장 → 게이트 서버가 `face/dataset`에 포함 → AI 서버가 다음 동기화 때 반영
4. 화면에 "AI 반영 대기 / 반영됨" 표시 (Q-13: AI 서버 데이터셋 재동기화 주기)
