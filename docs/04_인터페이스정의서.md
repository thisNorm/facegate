# 04. 인터페이스 정의서

버전 0.1 · 2026-10-27

## IF-1. AI 서버 ↔ 게이트 서버 (기존 규격 그대로)

출처: 기존 엣지 서버의 얼굴인식 API 연동 문서. 게이트 서버가 **엣지서버와 같은 경로·형식**을 제공해서 AI 프로그램은 서버 주소와 키만 바꾸면 되게 합니다.

- 기본 경로: `/api/modules/camera/ai`
- 인증: `X-Ingest-Key` 헤더 — 관리자 설정(A-10)에서 발급한 키를 AI 서버 설정에 적어 매 요청에 보냄 (D-36). 없거나 틀리면 401
- 시각: 한국 시간 `YYYY-MM-DD HH:mm:ss`
- 이미지: `data:image/jpeg;base64,...`

| ID | 메서드·경로 | 방향 | 용도 | 게이트에서의 의미 |
|---|---|---|---|---|
| IF-1-1 | `GET /rtsp` | AI → 게이트 서버 | 분석할 카메라 목록 | **안드로이드 단말의 RTSP 주소** 목록. AI 계약의 `device_key` = 게이트 서버의 단말 번호 `terminalKey` (단말 = 카메라, D-56) |
| IF-1-2 | `GET /face/dataset` | AI → 게이트 서버 | 등록 얼굴 목록 | **재직 중이고 얼굴 등록된 직원만** 포함. `worker_key` = 직원 ID |
| IF-1-3 | `GET /file/{worker_key}/{파일}` | AI → 게이트 서버 | 등록 얼굴 이미지 | 인증 필요 |
| IF-1-4 | `POST /face/appear` | AI → 게이트 서버 | 인물 감지 | **개방 판정 트리거** |
| IF-1-5 | `POST /face/disappear` | AI → 게이트 서버 | 인물 사라짐 | 기록 보완 (체류 시간) |
| IF-1-6 | `POST /power-on` | AI → 게이트 서버 | AI 시작 | 상태 표시 |
| IF-1-7 | `POST /status` | AI → 게이트 서버 | 1분 주기 상태, `cameras[]`의 `device_key`(= 단말 번호)별 `rtsp_ok` | 3분 미수신 시 오프라인 경보 |

### IF-1-4 appear 처리 규칙

요청 (기존 형식):
```json
{ "worker_key": 15, "is_worker": true, "device_key": 58,
  "appear_time": "2026-09-22 17:40:00",
  "full_frame": "data:image/jpeg;base64,...", "crop_frame": "data:image/jpeg;base64,..." }
```

처리:
1. `device_key`(= 단말 번호) → 어느 게이트의 단말인지 찾음. 없으면 `400`
2. `is_worker:false` → 판정 `UNREGISTERED`
3. `is_worker:true` → 직원 조회: 퇴사/정지 → `DENIED_INACTIVE`, 그 게이트 권한 없음 → `DENIED_GATE` (D-59, 시간대 권한은 없음)
4. 같은 직원이 같은 게이트에서 5초 안에 다시 허가되면 → 개방 생략, `DUPLICATE` 기록만
5. 허가 → 릴레이 펄스(IF-3) + 단말 알림(IF-2) **먼저**, 사진 저장은 그 뒤
6. 응답: `{ "event_key": <출입 기록 ID> }` (기존 형식과 같음)

> 확인 필요(Q-12): 미등록으로 판정된 객체가 나중에 직원으로 인식되면 `appear`가 다시 오는가? 오지 않으면 AI 서버에 "재인식 시 재전송" 요청이 필요합니다.

## IF-2. 게이트 서버 → 안드로이드 단말 (신규)

| 항목 | 값 |
|---|---|
| 방식 | WebSocket `wss://<게이트서버>/ws/terminal?gate_key=<게이트 번호>` |
| 인증 | `Authorization: Bearer <단말 토큰>`. 토큰은 단말 연결(IF-9) 때 서버가 만들어 단말에 한 번만 넘기고 DB에는 해시만 저장. 게이트는 토큰으로 정하므로 `gate_key`가 옛 값이어도 붙는다 |
| 단말 주소 알림 | 헤더 `X-Terminal-Addresses: <단말 IPv4>,...`. 서버는 지금 주소, 접속해 온 주소, 이 주소들, 127.0.0.1(adb 개발 연결) 중 RTSP 포트에 실제로 닿는 첫 주소로 영상을 받는다(공유기 너머 접속 대비) |
| 연결 해제 | 업그레이드 응답 401(토큰 폐기) 또는 닫기 코드 `4401`이면 해제된 단말. 단말은 재연결하지 않고 연결 정보를 지운 뒤 미연결 화면으로 간다 |
| 연결 유지 | 서버 30초마다 `ping`, 단말 60초 무응답 시 재연결 (1→2→4→…최대 30초 간격) |

서버 → 단말 메시지:

```json
{ "type": "decision", "event_key": 7301, "result": "GRANTED",
  "name": "홍길동", "department": "개발팀", "at": "2026-10-27 08:51:02" }
```
```json
{ "type": "decision", "event_key": 7302, "result": "UNREGISTERED" }
```
```json
{ "type": "status", "ai_online": true, "rtsp_ok": true, "gate_ok": true }
```
```json
{ "type": "config", "notice": "오늘 18시 소방 점검", "logo_url": "/asset/logo.png",
  "rtsp": { "user": "gate1", "password": "<서버 생성>", "width": 1920, "height": 1080, "fps": 15 } }
```

`result` 값: `GRANTED`, `UNREGISTERED`, `DENIED_INACTIVE`, `DENIED_GATE`, `GATE_ERROR`
- 거부 결과에는 **이름을 보내지 않습니다** (뒷사람에게 노출 방지).
- `DUPLICATE`는 단말에 보내지 않습니다.

단말 → 서버: `{ "type": "hello", "app_version": "1.0.0" }` (연결 직후 1회)

### 방문객 호출·손님 동반 (D-15)

```json
{ "type": "visitor_call", "request_id": "v-11…", "photo": "data:image/jpeg;base64,..." }
```
서버 → 단말 진행 상태:
```json
{ "type": "visitor_call_status", "request_id": "v-11…", "status": "WAITING" }
```
`status`: `WAITING` → `OPENED` / `REJECTED` / `TIMEOUT`(2분)

서버 → 관리자 웹: 관리자 화면도 WebSocket(`/ws/admin`)으로 `visitor_call` 알림을 받습니다 (사진, 게이트, 시각).

손님 동반 (허가 결과 화면에서):
```json
{ "type": "escort", "event_key": 7301, "guest_count": 2 }
```
- 서버는 `event_key`가 이 단말에서 5초 안에 나온 `GRANTED`인지 확인
- 직원 통과 후 추가 개방: 게이트가 **통과 완료 신호**를 주면 그때마다 1회 개방, 신호가 없으면 3초 간격으로 개방 (08 질의서 답변에 따라 확정)
- 각 추가 개방은 `access_log`에 `method: "ESCORT"`, `host_event_key`로 기록

### 핸드폰으로 열기 (D-62)

```
단말 → 서버  GET /api/terminal/pass-code            (단말 토큰)  → { "url": "https://gate.회사도메인:8443/m/pass?c=…", "expiresInMs": 60000 }
               기능이 꺼져 있으면(PHONE_BASE_URL 없음) 404
단말 → 핸드폰  NFC Forum Type 4 태그(AID D2760000850101), NDEF URI 레코드에 위 url. 같은 url을 QR로도
핸드폰 → 서버  GET  /m/pass?c=…                      (화면) → POST /m/api/pass { "c": "…" } + 쿠키 facegate_phone
               200 { "ok": true, "result": "GRANTED", "name": "홍길동", "gateName": "정문" }
               401 등록 안 된 핸드폰(값은 남음), 410 지났거나 쓴 값
서버 → 단말  decision 메시지 (얼굴과 같음). 출입 기록 method는 PHONE
```

등록: 관리자 `POST /api/admin/employees/:key/phone-invite` → `{ url: …/m/register?t=…, expiresAt }`(24시간, 한 번만). 핸드폰에서 `POST /m/api/register { t }` → 쿠키 `facegate_phone`(HttpOnly, SameSite=Strict, 경로 /m, 2년). 목록 `GET /api/admin/employees/:key/phones` → `{ enabled, phones[] }`, 해제 `DELETE /api/admin/phones/:phoneKey`. 작업 이력 `PHONE_INVITE`, `PHONE_REVOKE`. `/m`의 쓰기 요청은 다른 사이트에서 오면 403.

### 단말 안 얼굴 인식 (D-63)

설정 '얼굴 인식 위치'가 단말일 때만 쓴다. 단말 토큰으로 인증하고, 본문 모양은 AI 서버 연동(IF-1)과 같다.

```
단말 → 서버  GET  /api/terminal/face/dataset   → { "enabled": true, "faces": [{ "worker_key": 7, "image_path": ["/face/file/7/abc.jpg"] }] }
               꺼져 있으면 { "enabled": false, "faces": [] }
단말 → 서버  GET  /api/terminal{image_path}     → JPEG (꺼져 있으면 404)
단말 → 서버  POST /api/terminal/face/appear    { "worker_key", "is_worker", "appear_time", "full_frame", "crop_frame" }
               → { "event_key" }. device_key는 보내도 무시하고 토큰의 단말로 정한다. 꺼져 있으면 409
서버 → 단말  decision 메시지 (AI 서버 때와 같음)
```

모르는 사람은 `is_worker: false`, `worker_key`는 단말이 매기는 사람 번호. disappear(머문 시간)는 아직 보내지 않는다. 설정은 `GET/PUT /api/admin/settings/face-engine` `{ "engine": "AI_SERVER" | "TERMINAL" }`, 작업 이력 `SETTINGS_UPDATE`.

### NFC 태그 (단말 → 서버 → 단말) — D-12

```json
{ "type": "nfc_tap", "request_id": "b1f3…", "picc_data": "EF963FF7828658A599F3041510E5D1FE", "cmac": "94EED9EE65337086", "at": "2026-10-27 08:51:02" }
```
- 단말은 스티커의 NDEF(URL 형태)에 들어 있는 `picc_data`(암호화된 UID+읽기 카운터)와 `cmac`을 그대로 보냅니다. 단말은 내용을 해석하지 않습니다.
- 서버 처리 순서: ① `picc_data`를 SDM 메타 키로 복호화 → UID·카운터 ② UID로 스티커별 키 파생 → `cmac` 검증 (불일치 = `DENIED_CARD_FORGED`) ③ 카운터 ≤ 저장된 마지막 값 → `DENIED_CARD_REPLAY` ④ 카운터 저장 ⑤ FR-N-05 규칙으로 판정 → 허가 시 릴레이 개방 → 같은 `decision` 메시지에 `request_id`와 `method: "NFC"`를 넣어 응답
- 단말은 1초 안에 응답이 없으면 "다시 대주세요" 표시 (재전송 1회)

```json
{ "type": "decision", "request_id": "b1f3…", "method": "NFC", "event_key": 7310, "result": "GRANTED", "name": "홍길동", "department": "개발팀" }
```
`result` 추가 값: `DENIED_CARD_UNKNOWN`(발급 기록 없는 스티커), `DENIED_CARD_LOST`(분실·정지·회수), `DENIED_CARD_FORGED`(CMAC 불일치 → 경보), `DENIED_CARD_REPLAY`(카운터 재사용 → 경보), `NEED_NFC`·`NEED_FACE`(`얼굴+NFC` 시간대에 한쪽만 들어옴 → 단말 T-02-1, 10초 대기)

### NFC 스티커 발급 (단말 관리자 모드, APDU 중계) — D-12

키가 단말에 남지 않도록, 스티커와의 암호 대화는 서버가 하고 단말은 중계만 합니다.

```
관리자: T-07에서 직원 선택 → 새 스티커를 댐
단말 → 서버  { "type": "nfc_provision_start", "provision_id": "p-81…", "employee_key": 15, "uid": "04A1B2C3D4E5F6" }
서버 → 단말  { "type": "nfc_apdu", "provision_id": "p-81…", "seq": 1, "apdu": "9071000002000000" }
단말 → 서버  { "type": "nfc_apdu_result", "provision_id": "p-81…", "seq": 1, "response": "…91AF" }
  … (인증 → 키 변경 → NDEF 템플릿 기록 → SUN 설정, 수십 회 반복)
서버 → 단말  { "type": "nfc_provision_done", "provision_id": "p-81…", "result": "OK" }
```
- 단말은 스티커를 떼면 `nfc_provision_abort`를 보내고, 서버는 그 발급을 취소합니다. 중간에 끊겨도 다시 대면 처음부터 진행 (이미 키가 바뀐 스티커는 서버가 파생 키로 인증해 이어서 처리).
- 마지막 단계에서 스티커를 한 번 읽어 SUN 검증이 통과해야 `OK` (FR-N-15).
- 단말 토큰 + 관리자 PIN 세션이 있어야만 시작 가능.

얼굴 판정의 `decision`에는 `method: "FACE"`를 넣습니다.

## IF-3. 게이트 서버 → 스피드게이트 (게이트 제어 어댑터) — D-27

게이트는 시설 쪽에서 따로 선정하므로, 게이트 서버는 **게이트 종류와 상관없는 공통 명령**만 쓰고, 실제 신호 방식은 **어댑터**로 갈아끼웁니다. 게이트가 정해지면 08 질의서로 프로토콜을 받아 어댑터 하나만 새로 만듭니다.

### 공통 명령 (게이트 서버 내부 인터페이스)

| 명령 / 이벤트 | 설명 |
|---|---|
| `open(gate, direction, count=1)` | 열기. `direction` = `IN`/`OUT`, `count` = 통과 허용 인원(손님 동반용) |
| `health(gate)` | 게이트·제어 장치와 통신 되는지 |
| `on_passed(gate, direction)` (선택) | 게이트가 "통과 완료" 신호를 줄 때 |
| `on_alarm(gate, type)` (선택) | 꼬리물기·역진입·강제 진입 경보 |

게이트가 지원하지 않는 선택 이벤트는 어댑터가 "지원 안 함"으로 알리고, 게이트 서버는 그에 맞춰 동작합니다 (예: 통과 신호가 없으면 손님 동반은 시간 간격으로 개방).

### 어댑터 후보

| 어댑터 | 게이트 쪽 입력 | 우리 쪽 장비 | 상태 |
|---|---|---|---|
| **드라이 접점** | 무전압 접점 열림 입력 (가장 흔함) | 네트워크 릴레이 모듈 (Modbus TCP / HTTP) | **PoC 기본** (LED로 게이트 대체) |
| RS-485 | 제조사 시리얼 프로토콜 | RS-485 ↔ 이더넷 변환기 | 게이트 선정 후 |
| TCP/IP | 제조사 네트워크 명령 | 없음 (직접 통신) | 게이트 선정 후 |
| Wiegand | 카드 번호 입력 방식 | Wiegand 출력 모듈 | 게이트 쪽에 출입 컨트롤러가 있을 때 |

### 공통 규칙
- 열기 명령은 300ms 안에 응답이 없으면 1회 재시도, 실패 시 `GATE_ERROR`
- 열림 신호는 항상 **게이트 서버에서만** 나갑니다 (단말·AI는 게이트에 직접 신호를 보내지 않음)
- 게이트별 어댑터 종류·주소·채널은 관리자 웹 게이트 관리(A-07)에서 설정

## IF-6. 안드로이드 단말 → AI 서버 (영상 송출, 안 B)

| 항목 | 값 | 비고 |
|---|---|---|
| 방식 | 단말 앱 안의 RTSP 서버, AI 서버가 접속해 받아감 (pull) | 기존 CCTV와 같은 방식 |
| 주소 | `rtsp://<사용자>:<비밀번호>@<단말 고정 IP>:8555/` | 단말 등록 시 게이트 서버에 저장 → `GET /rtsp`로 AI에 제공 |
| 코덱 | H.264 (하드웨어 인코딩) | AI 서버가 기존 CCTV에서 읽는 코덱과 같아야 함 (Q-21) |
| 해상도·프레임 | **1920×1080, 약 15fps** (WA8059T에서 송출 확인) | 부하가 크면 720p로 낮춰 비교 (PoC) |
| 비트레이트 | 약 3.24Mbps (확인값) | 레인 3개 = 약 10Mbps, 사내 유선망에서 여유 |
| GOP | 1초 (15프레임) | 접속 직후 첫 화면까지 지연 단축 |
| 인증 | RTSP Basic/Digest 인증 + AI 서버 IP만 허용 | |
| 비밀번호 | 단말 등록 시 게이트 서버가 생성해 단말에 전달 (IF-2 `config` 메시지) | |

단말 → 서버 상태 보고 (IF-2 WebSocket, 30초마다):
```json
{ "type": "health", "streaming": true, "rtsp_clients": 1, "fps": 15, "cpu_temp_c": 52, "uptime_sec": 86400 }
```
`rtsp_clients: 0`이 1분 넘게 지속되면 = AI가 영상을 안 받고 있음 → 대시보드 경보.

## IF-4. 게이트 서버 → 원격 관리 서버

## IF-7. 관리자 인증 (1차 P1, P3 갱신)

|---|---|---|---|

- `admin`은 `{ adminKey, loginId, name }`, `mustChangeCredentials`는 boolean, `appEnv`는 `development` 또는 `production`이다. 단말 응답은 기존 계약을 유지한다.
- 첫 관리자는 서버 시작 시 관리자가 한 명도 없을 때 `.env`의 `INITIAL_ADMIN_ID`, `INITIAL_ADMIN_PASSWORD`로 만든다. 이름은 아이디와 같고 `must_change_credentials = 1`이다. 둘 중 하나라도 비면 생성하지 않고 경고 한 줄을 남긴다. 실제 값은 문서, 예시 파일, 로그에 쓰지 않는다 (D-45).
- A-00 계정 정보 확인은 로그인 뒤 `mustChangeCredentials`가 참일 때만 보여 준다. 아이디와 비밀번호를 바꾸거나 그대로 유지할 수 있으며 두 동작 모두 현재 비밀번호가 필요하다. credentials 요청에서 생략한 항목은 유지하고, 성공하면 표시를 지운다. 빈 `newPassword`는 유지가 아니라 400이다. 실제로 변경하면 현재 세션 외의 세션을 삭제한다.
- credentials 작업 이력은 실제 변경이 없으면 `CREDENTIALS_CONFIRM`, 있으면 `CREDENTIALS_CHANGE`다. detail에는 `{ loginIdChanged, passwordChanged }`만 기록하고 아이디와 비밀번호 값은 남기지 않는다.
- `APP_ENV`가 비었거나 없으면 `production`이다. `development`에서만 개발 전용 `dev` 계정을 만들거나 비밀번호를 `1234`로 되돌리고 첫 로그인 표시를 0으로 둔다. 개발 시작 시 경고 한 줄을 남긴다. `production` 시작 때 이 계정이 있으면 세션과 함께 삭제하고 경고한다. `dev`는 서버가 관리하는 예약 계정이므로 초기 계정 아이디로 지정할 수 없다. 개발 웹은 맨 위에 개발 모드 줄을 보여 준다 (D-46).
- 관리자 추가, credentials 변경, 내 비밀번호 변경은 비밀번호가 빈 문자열일 때만 400이다. 길이와 복잡도 규칙은 없고 공백도 임의로 지우지 않는다. 로그인 5회 실패 시 10분 잠금은 유지한다 (D-47).
- 업무 API(`/api/admin/*`)는 로그인 세션만 받는다. 로그인은 세션 발급을 위한 예외다. PoC의 `X-Admin-Key`는 없앴다. 다른 사이트에서 온 쓰기 요청은 `Origin`, `Sec-Fetch-Site` 검사로 403이다.

## IF-9. 단말 연결 (D-57)

단말에서는 아무것도 입력하지 않는다. 연결 정보 `{ terminalKey, token, gateKey, gateName, rtspUser, rtspPassword, serverUrls }`는 서버가 만들어 한 번만 넘긴다. `serverUrls`는 서버의 IPv4 주소들과 `127.0.0.1`(마지막)로, 단말이 차례로 `GET /api/terminal/hello`해 먼저 답하는 주소를 쓴다.

| 방법 | 흐름 |
|---|---|
| QR (단말 → 서버) | 관리자 웹이 코드를 발급해 QR `facegate://pair?code=<6자리>&u=<서버 주소>&u=...`를 보여 줌 → 단말이 읽고 `POST /api/terminal/pair` |
| 번호 (서버 → 단말) | 미연결 단말 화면에 단말 주소와 6자리 번호 → 관리자가 웹에 입력 → 서버가 `POST http://<단말 주소>:8556/pair` |

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/terminal/hello` | 인증 없음 | `{ app: 'FaceGate' }` |
| `POST /api/terminal/pair` | 인증 없음. `{ code, model, appVersion, rtspPort }` | 200 연결 정보 / 400 형식 / 401 `INVALID` / 410 `EXPIRED`·`USED` / 429 `LOCKED`(같은 주소 5번 틀리면 10분) |
| 단말 `POST :8556/pair` | 미연결일 때만 열림. `{ pin, ...연결 정보 }` | 200 `{ model, appVersion, rtspPort }` / 401 번호 틀림(5번이면 번호 교체) / 400 형식 |
